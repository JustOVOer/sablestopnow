# GUI 逻辑总表（排查用）

> 目的：把「有哪些 GUI、每个 GUI 有什么控件、点下去会发生什么、状态怎么变」写成一张可对照的链路图。
> 你按这份表指出「这一条没做到 / 这一条不该这样」，我按行号改。
>
> 记号：**✅** = 已实机验证过；**⚠** = 我知道不一致或可疑（末尾 §12 汇总）；**TODO** = 我不确定，没有猜。

---

## 0. 怎么读 / 怎么查

- 每一节的形式是：**控件 → 点击后 → 状态变化 → 你看到什么**。
- **动作栏提示**：`ModelMode.prompt("key")` = 屏幕正下方那行淡出文字（不是面板里的提示条）。
- **面板顶部提示条**：`model.hud` 层，内容是「当前功能」的固定说明，不随操作变化。
- **命令名**：所有状态变更都经 `Cmd.run("名字", ...)`；按 **F9** 会把每个控件的树、每个状态的读写次数、每个命令的派发次数写成 `run/ui-lint.txt`。
- **日志开关**：`[model-diag]`（模型模式：悬停、点击、工具、投影、描边）、`[ui-diag]`（每次鼠标按下落到哪个控件）、`[ui-lint]`（自检与布局塌陷）。

## 2. 界面层清单（模型模式）

模型模式的五个面板**不是 Screen**，是覆盖层（`UiLayer`）—— 所以可以一边看世界一边点界面，也不会被别的模组 `setScreen` 顶掉。

| 层名 | 位置 | 内容 | 吞鼠标 | 吞按键 | 参与避让 | 备注 |
|---|---|---|---|---|---|---|
| `model.picks` | 全屏覆盖 | 屏幕空间的选择标记（黄/橙） | 否 | 否 | 否 | 最底层，只画不接受输入 |
| `model.top` | 屏幕顶部，高 36 | 上边栏（两行） | 是 | 是 | 是 | `hud=true`，从上边滑入 |
| `model.tree` | 右侧，宽 = 屏宽×0.24（92..150） | 树状图 + 底栏两个按钮 | 是 | 是 | 是 | 可折叠 |
| `model.left` | 左侧，宽 = 屏宽×0.26（96..160） | 编辑区 + 底栏 完成/取消 | 是 | 是 | 是 | 可折叠，从左边滑入 |
| `model.hud` | 顶部（上边栏下方） | 「当前功能」说明条 | 是 | 是 | 是 | ⚠ 与左右栏顶部重叠，见 §12.1 |

**输入优先级 = 打开顺序的倒序**（后开的在上面，先拿到事件）。左右栏各自用 padding 从 `TOP_H+8` 开始，`model.hud` 从 `TOP_H+6` 开始。

## 3. 模型模式 · 上边栏（`model.top`）

两行，**上行永远是「做什么」，下行永远是「在哪一页」**（这是你要求的 SW 式排布）。

### 3.1 下行：功能类型标签页（`Tabs`）

| 标签 | 点击后 |
|---|---|
| 配合 \| Mates | 切到配合页 **并且**直接进入配合流程（`startTool(MATE)`）；清掉已选参考 |
| 模型 \| Model | 切页；若当前是配合类工具则退出到「无工具」 |
| 视图 \| View | 切页；同上 |

标签当前页由 `Prop<String> "model.tab"` 保存 —— 重建上边栏不会跳回第一页。
选中条会从旧位置**滑到**新位置（`Anim`，可被「界面动画」开关关掉）。

### 3.2 上行：当前页的功能按钮

**配合页**

| 按钮 | 点击后 |
|---|---|
| 新建配合 \| New mate | `startTool(mate)`：工具=配合，清空已选；左栏提示「再选 1 个」 |
| 比例配合 \| Ratio | `startTool(ratio)`：需要 ≥3 个参考，最后选的是基准 |
| 齿轮配合 \| Gear | `startTool(gear)`：按顺序选 4 条线段 |

**模型页**

| 按钮 | 点击后 |
|---|---|
| 正视此面 \| Normal to | `startTool(normal_to)`：**一点即生效**，点模型上任意面就把相机转到正对该面（不需要点完成） |
| 施力点 \| Force | `startTool(force)`：进入放置模式，鼠标划过的面出现落点预览 |
| 隐藏/显示 \| Hide | 切换**当前选中模型**的隐藏位；隐藏后描边与拾取都跳过它，树里仍然保留（带「(已隐藏)」标签） |
| 删除配合 \| Delete mate | 删除当前选中的配合（选的是耦合就删耦合）；没选中时给提示 |

**视图页**

| 按钮 | 点击后 |
|---|---|
| 前 / 后 / 左 / 右 / 上 / 等轴测 | 相机缓动到对应预设朝向 |
| 适配 \| Fit | 有选中模型 → 对准它**并按包围盒重新定距**；否则距离设为 16 |
| 居中 \| Center | 把选中的模型摆到视野正中，**不改距离**（与「适配」的区别就在这儿） |

> 选中模型本身**不再移动相机**。想「看它」用「居中」（不改缩放）或「适配」（改缩放）。

按钮是**切换型**的：当前工具的按钮会保持高亮（`toggled`）。

## 4. 模型模式 · 左边栏（`model.left`）

### 4.1 常驻部分

- 顶部标题：`model.left.title`（一行操作说明，**⚠ 被 `model.hud` 提示条压住一部分**）
- 内容区：`ScrollPane`（内容超高时可滚轮/拖滚动条）
- 底栏：**完成** / **取消** 两个等宽按钮

### 4.2 内容按状态分支（自上而下第一条命中的生效）

| 顺序 | 条件 | 内容 |
|---|---|---|
| 1 | 工具 = 配合 | 已选 <2：提示再选；≥2：**配合编辑页**（§9.1，草稿模式） |
| 2 | 工具 = 施力点 **或** 有选中的施力点 | 施力点编辑器（见 §8.2） |
| 3 | 有选中的耦合组 | 比例/齿轮编辑器（见 §10） |
| 4 | 工具 = 比例 / 齿轮 | 说明 + `已选 n / 需要 m` |
| 5 | 工具 = 正视此面 | 一行说明（点面即生效） |
| 6 | 树里选中了一条配合 | **配合编辑页**（§9.1，编辑模式 —— 与创建页完全同一个页面） |
| 7 | 其它（无工具） | 浏览：选中模型 id + 配合数量 + 「点模型或树选择」 |

顶部永远还有：当前工具标题、`已选 n 个元素`、以及需要几个。

### 4.3 完成 / 取消

| 按钮 | 语义 | 点击后 |
|---|---|---|
| **完成** | 结束当前这次操作，**保留**已产生的结果 | 见下表 |
| **取消** | **放弃**当前操作 | 清掉施力点选中、耦合选中、工具、已选参考；重建上栏与左栏 |

完成的分派（**顺序很重要**）：

| 优先级 | 条件 | 结果 |
|---|---|---|
| 1 | 工具=施力点 **或** 正在编辑某个施力点 | 结束施力点编辑 + 工具归零 + 提示「施力点编辑结束」 |
| 2 | 正在编辑耦合组（且工具不是比例/齿轮） | 结束耦合编辑 + 提示 |
| 3 | 正在编辑一条配合（且工具不是配合） | 结束配合编辑 + 提示 |
| 4 | 工具=正视此面 | 对鼠标下的面执行「正视此面」（有面才动） |
| 5 | 工具=配合 | 已选 <2 → 提示；否则把**创建页的整套草稿**（类型/数值/区间/翻转/名字）随创建命令发出 |
| 6 | 工具=比例 | 参考不够 → 提示；够了 → 发包建组 |
| 7 | 工具=齿轮 | 参考不是 4 条 → 提示；是 → 发包建组（默认 20:40） |
| 8 | 其它 | 清参考、工具归零、提示「当前没有正在进行的操作」（**不再是什么都不发生**） |

**完成按钮的可用性**：当且仅当「有工具在跑 **或** 正在编辑施力点 / 耦合组 / 配合」时可点。
> ⚠ 这条是这一轮才修对的：以前只看「有没有工具在跑」，所以**从树里点进一个施力点去编辑时「完成」是灰的**（你反馈的「编辑施力点时无法点击完成，创建施力点时却可以」）。

**取消** 同理：以前只清工具，不清施力点/耦合的选中，于是左栏看起来「取消失败」。

## 5. 模型模式 · 右边栏：树状图（`model.tree`）

### 5.1 树的结构

```
模型 45ba82a6
├─ 配合 | Mates
│   ├─ <每条标准配合一行>
│   └─ 比例 | Ratio (n)  /  齿轮 | Gear 20:40 [R]
├─ 属性 | Properties
│   ├─ ☐ 隐藏 | Hidden
│   ├─ ☑ 碰撞 | Collision
│   └─ ☑ 锁定 | Locked
└─ 可控施力点 | Force points
    ├─ <8 位 id + 力量 N + (off)>
    └─ ＋ 添加施力点 | Add force point
```

树的展开状态跨刷新保留（按 key 记忆）。隐藏的模型仍然留在树里（带 `(已隐藏)`）。

### 5.2 点击一行的行为

| 行的类型 | 左键点击后 |
|---|---|
| 模型 | 选中它（相机不动）；清掉其它三种选择 |
| ＋ 添加施力点 | 直接进入施力点放置流程 |
| 施力点 | 左栏打开它的编辑器，并**自动把相机对准它** |
| 标准配合 | 左栏显示这条配合的详情 + 删除入口（高亮） |
| 比例 / 齿轮组 | 左栏打开对应编辑器 |
| 属性行（隐藏/碰撞/锁定） | 切换该位（点行任意处都行，不只是小方块） |
| 分支标题行（配合/属性/可控施力点） | 展开/收起 |

**四种选择互斥**（模型 / 配合 / 施力点 / 耦合）—— 这是「左栏不跟随树选择」的修复：以前施力点的选择会一直霸占左栏。
**右键**点配合行 = 只高亮，不改左栏其它内容。

### 5.3 底栏

| 按钮 | 点击后 |
|---|---|
| 刷新 \| Refresh | 立刻重建整棵树 |
| ＋ 添加施力点 | 进入施力点放置流程 |

### 5.4 右键菜单（在世界上按右键，不是树上）

| 项 | 点击后 |
|---|---|
| 隐藏/显示 | 同 §3.2 的隐藏按钮 |
| 删除配合 | 同 §3.2 |
| ——（分隔线） | — |
| 前视 | 相机转到 FRONT |
| 等轴测 | 相机转到 ISO |
| 适配 | 同 §3.2 |

菜单挂在 `model.tree` 层上（所以它不会被左栏挡住），并用 `Ui.toFront` 提到最前。

### 5.5 空格键的视图菜单

在世界上按 **空格** → 屏幕中上方弹出「前/后/左/右/上/下/等轴测」菜单（挂在 `model.top` 层上）。
Esc 关闭；再按空格不会重复开。

## 6. 模型模式 · 世界输入

| 输入 | 条件 | 结果 |
|---|---|---|
| **W / S** | 光标不在输入框里 | 沿视线的**水平分量**前后平移（俯视时也是「往前」而不是「往下」） |
| **A / D** | 同上 | 左右平移 |
| **方向键上 / 下** | 同上 | 垂直上 / 下平移 |

> 六个键都是可改键的 `KeyMapping`（「选项 → 按键控制 → sablestopnow」）。
| **中键拖动** | 光标不在面板上 | 绕轨道中心旋转 |
| **Ctrl + 中键拖动** | 同上 | 平移视野 |
| **Shift + 中键拖动** | 同上 | 上下拖 = 缩放 |
| **滚轮** | 同上 | 缩放（只改距离，不动目标点） |
| **左键点击** | 光标在面板上 | 由 GUI 处理，不透到世界 |
| **左键点击** | 工具=**无** | 选中鼠标下的模型（**不动相机**），并作为「可能要拖动」的候选 |
| **左键点击** | 工具=**正视此面** | 立刻正视鼠标下的面，工具自动结束 |
| **左键点击** | 工具=**施力点** | 在鼠标下的面放置一个施力点（力方向 = 该面法线），自动选中它 |
| **左键点击** | 工具=配合/比例/齿轮 | 加入选择（数量到上限时提示）；**光标必须停在屏幕标记上**，否则提示「把鼠标移到标记上再点击」 |

## 7. 模型模式 · 屏幕标记与提示

### 7.1 选择标记（`model.picks` 层，屏幕空间）

鼠标划过模型时，**候选画在屏幕上**而不是高亮在模型上（SolidWorks 式，因为三维判定区在屏幕上只有两三像素，玩家看不到可点范围）：

| 候选 | 标记 |
|---|---|
| 点（角点 / 面心 / 棱心 / 结构中心） | 9×9 小方块（带深色描边） |
| 棱 | 一条线段（比点宽），两端各一个小方块 |
| 面 | 四角带直角标记的四边形轮廓 + 极淡填充 |

颜色：**黄** = 候选；**橙** = 光标已经停在标记上（这时点击才被接受）。
已选中的参考画在**模型**上（青色，`ModelRenderer.drawPicked`）。

### 7.2 模型描边

- 每个可见模型一圈细线；选中的那个换暖色加粗。
- 描边**按方块碰撞箱**取形状（半砖只描半格、楼梯描出台阶轮廓）。
- 平坦表面**不画**内部接缝（只留外轮廓）。
- **带深度测试**：被方块挡住的线不画。以前是不穿透的（`BOXES_NO_DEPTH`），
  于是远处模型 + 结构内部每一格的棱全叠在一起，画面糊成一片（你反馈的「描边不要穿透显示」）。

### 7.3 施力点标记（画在模型上）

| 颜色 | 含义 |
|---|---|
| 绿 | 已启用 **且** 频道配好 |
| 琥珀 | 已启用但频道没配好（放了不会动 —— 最容易以为「坏了」的情况） |
| 灰 | 未启用 |
| 黄 | 放置模式下的**落点预览**（跟着鼠标在表面上走） |

每个标记 = 一个和小方块 + 一条沿表面法线的箭头（箭头方向 = 施力方向）。

**锁定的结构不受施力点影响**：施力点会跳过处于锁定状态的结构。
向运动学体施加冲量不会当场变成速度，而是堆在求解器里 —— 锁定一解除就一次性释放，
表现就是「锁定的模型被 200N 的力瞬间吹飞」（你反馈的第 2 条）。跳过的次数会打
`[model-diag] force skipped on locked bodies: N point-substeps in 3s`。

### 7.4 顶部提示条（`model.hud`）

显示**当前功能**的固定说明（`model.tool.*.hint`），随工具切换而变；与上边栏一起滑入。

## 8. 施力点：完整链路

### 8.1 放置（新建）

1. 触发方式（三种任选）：上边栏「模型」→「施力点」／树底栏「＋ 添加施力点」／树里「＋ 添加施力点」
   → `startTool(force)`：工具=force，清空已选，左栏换成「施力点」提示 + 编辑器（此时还没有点，显示「还没有选中施力点」）。
2. 鼠标在模型表面移动 → 该面出现**黄色落点预览** + 屏幕上出现对应的选择标记。
3. 左键点击表面 → `ForceNetworking.sendCreate(模型, 方块, 面, 局部点, 默认力量, **false**)`
   → 服务端建点并**全量广播** → 客户端拿到新点 → `ModelForceUi` 用「已知点集合」做差集，**自动选中新点** → 左栏变成它的编辑器。

   ⚠ **新建的点默认是「未开启」的**。以前建出来就是开启的，于是「频道上已经有信号 → 一落点模型立刻飞走」。
   现在必须由玩家在左栏勾上「开启」才真正施力。
4. 在左栏调力量 / 频道 / 名字 / 开关（见 §8.2）。
5. **完成** → 放掉施力点选中、清参考、工具归零、提示「施力点编辑结束」。
   （想继续放：再点一次「施力点」按钮，或直接再点一次表面？——**只有工具还在 force 时才继续放**，完成后需要重新进入。 TODO 这一条要不要改成「完成后保持放置模式」请你定。）

### 8.2 编辑（已有的点）

| 控件 | 点击/操作后 | 状态变化 |
|---|---|---|
| 力的大小（标签 + 滑条 + 输入框） | 拖滑条 → 输入框**逐帧**跟着变；在输入框打字 → 滑条**立刻**跟着滑 | 两者绑同一个 `Prop<Double> force.magnitude`；拖动中只改本地值，**松手**才发一次命令 |
| 无线红石频道①（可输入 + 实时补全） | 打字筛物品注册名；从列表点一条 | 写 `Prop force.channel1`，并把频道①发给服务端 |
| 无线红石频道②（同上） | 同上 | 频道②留空 = 与①相同（旧存档兼容） |
| 自定义名（可选） | 回车 / 失焦提交 | 写 `force.channelName` |
| 开启 \| Enabled | 勾选 | 立刻发命令（力只在开启时施加） |
| 删除施力点 | 点击 | 发包删点，并清掉左栏选中 |

**为什么还需要「完成」**：编辑器是「选中即显示」的，不主动放掉选中，左栏会一直停在这个点上。

### 8.3 力量复位问题（本轮修）

**现象**：拖动滑条后不久力量又变回 0。
**根因**：包体里 `magnitude` 是**非空 double**，`requestUpdate(null)`（只改频道/名字/开关时）被写成了 `0.0` —— 于是「只改频道」的包顺手把力量清零，服务端照收，下一次全量同步就把滑条拉回 0。
**修**：用 `NaN` 当「这一项不改」的哨兵；再加一层：拖动过程中也进入「静默期」，避免周期性拉取把手底下的滑条拽走。

## 9. 配合 / 比例 / 齿轮：链路

### 9.1 标准配合

**创建页和编辑页是同一个页面**（同一组控件）：

| 控件 | 创建流程（草稿） | 编辑已有配合 |
|---|---|---|
| 配合类型（下拉框） | 只改本地草稿；换类型顺带把数值复位成新类型的默认值 | 立刻发 `changeType`（服务端会重新求解并吸附） |
| 数值 / 区间下限-上限（按类型出现） | 只改草稿 | 立刻发 `setValue` / `setRange` |
| 翻转（只有支持对齐的类型才有） | 只改草稿 | 立刻发 `setFlip` |
| 名字 | 只改草稿 | 立刻发 `rename` |
| 删除按钮 | 无（还没建出来） | 有 |

按类型的输入框：

| 类型 | 输入框 |
|---|---|
| 重合 / 平行 / 垂直 / 锁定 | 无（只有类型 + 翻转 + 名字） |
| 距离 | 一个数值（方块） |
| 角度 | 一个数值（度） |
| 限制 | 两个数值（下限、上限） |

流程：
1. 上边栏「配合」标签页（或点标签页本身）→ `startTool(mate)` → 左栏变成创建页（草稿复位）。
2. 依次点两个元素（点/棱/面/结构中心/基准面）。每次点击都要**光标停在屏幕标记上**。
3. 在创建页里选类型、填数值/区间、勾翻转、填名字 —— **这些都会一起随创建命令发出去**。
4. **完成** → 发包建配合 → 服务端求解吸附位姿 → 结构缓慢移动到位 → 树里该模型下的「配合」出现新条目。

**改动被拒绝时界面怎么表现**：改类型/改数值都可能被服务端拒绝（过约束、重复、吸附太远……）。
这里不做乐观锁定：改动写进状态后有一小段静默期，静默期一过就从服务端同步的值重新拉一遍 ——
被接受时拉回新值（界面不动），被拒绝时拉回旧值（**界面自动退回**），同时服务端会发一条拒绝原因。

### 9.2 比例

「配合」页 →「比例配合」→ 选**≥3 个面**（最后一个 = 基准）→ 完成。
树的「配合」分支下出现「比例 | Ratio (n)」→ 点它 → 左栏每行一个 `k`，改 `k` 下一个物理子步生效。

### 9.3 齿轮

「配合」页 →「齿轮配合」→ 按顺序选 4 条线段（固定轴A、齿轮轴A、固定轴B、齿轮轴B）→ 完成（**默认 20:40**，暂时没有建组前填齿数的界面 —— TODO 见 §12.3）。
树的「配合」分支下出现「齿轮 | Gear 20:40」→ 点它 → 左栏可改齿数 A/B、勾「反转」，并显示当前传动比。
