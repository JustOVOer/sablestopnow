# 特征树设计（对齐 SolidWorks 的 FeatureManager）

> 目的：**让"草图和拉伸的关系"有明确归属，从而保证各种要素可改，并给贴图一个自然的挂载点。**
> 依据 SolidWorks 官方文档与 GoEngineer 的说明（见文末引用）。

## 1. SolidWorks 的既有约定（查证结论）

| 约定 | 内容 |
|---|---|
| **草图被"吸收"** | 草图刚建出来时是树里的顶层项；**一旦被某个特征用掉，就吸收到该特征下面**（要展开特征才看得到）。这称为 *absorbed sketch*。 |
| **编辑特征 ≠ 编辑草图** | 双击特征 = 改特征参数（深度、角度…）；右键 → **Edit Sketch** = 进去改草图轮廓。两者是**分开的入口**。 |
| **回滚条（Rollback Bar）** | 拖到"特征与它的草图之间"可以临时把草图取出来（unabsorb）；也可以把模型回滚到某个历史点。 |
| **外观不是特征** | 颜色/贴图（Appearance）**不占特征树的一步**，它在 **Display Manager** 标签页里，作用层级是 **零件 / 实体 / 面**。 |

**关键推论**：SolidWorks 把"几何历史"（特征树）和"外观"（Display Manager）**分成两套视图**，因为
**外观不参与几何重算** —— 改贴图不该让模型重建。

## 2. 映射到我们的模型

我们现在是：`子结构 → 草图（顶层）→ 实体（引用草图）`。
**问题和 SolidWorks 早期一样**：草图是顶层项，实体只是"引用它的东西"——
于是"这张草图被谁用、改草图会影响谁"在树里看不出来。

**目标形状**：

```
子结构（ServerSubLevel，相当于"零件"）
├─ 基准面（前/上/右，还没做）
├─ 拉伸1  (Shape.Extrusion)
│   └─ 草图1                    ← 被吸收，展开才见
├─ 旋转1  (Shape.Revolution)
│   └─ 草图2                    ← 被吸收
└─ 草图3                        ← 没被任何特征用掉的，留在顶层（对应"未被吸收"）
```

规则：
1. **被"用掉"的草图移到该特征下面**（吸收）。判据：存在实体的 `sketchId` 指向它。
2. **没被用掉的草图留在顶层** —— 这就是 SolidWorks 的"未被吸收草图"，玩家一眼能看出哪张还没用。
3. **一张草图被多个特征引用**时，**在每个特征下都显示**（同一 id 多处出现）。
   SolidWorks 也允许一个草图驱动多个特征；显示上按"引用它的每个特征各挂一份"更直观。
   ⚠ 展开状态要按 **特征 id + 草图 id** 做 key，不能只按草图 id（否则两处会同时展开/折叠）。
4. **外观不进特征树**。它有独立入口（见 §3），因为改贴图**不该触发几何重算**。

## 3. 贴图挂在哪：**挂在特征（实体）上，但用独立入口**

我们是"一个实体一种贴图"，所以数据上它属于实体（`Solid.appearance`，已实现）。
但**交互上要像 SolidWorks 的 Display Manager**：

- 特征树里可以右键实体 → **"设置贴图…"**（快捷方式）；
- 同时左栏有一块**独立的外观区**，列出当前结构下所有实体及其贴图 —— 这就是我们的 Display Manager；
- 两者改的是同一份数据，**不产生两套状态**。

**为什么不做成"贴图特征"**：那样改一次贴图会让模型重算一遍几何（我们现在的重建路径是
"实体变了 → 重算碰撞盒"）。贴图和几何无关，硬塞进同一条链路只会让两边都变慢、都更容易错。

## 4. 编辑入口（保证"各种要素可改"）

树里每个节点要有**各自**的编辑入口，不要挤在一个面板里：

| 节点 | 入口 | 改什么 |
|---|---|---|
| 拉伸/旋转（特征） | 单击选中 → 左栏出现该特征的参数 | 深度/方式；轴/角度/旋向 |
| 被吸收的草图 | 特征下的草图行 → **"编辑草图"** | 进去画图（现有草图编辑器） |
| 未被吸收的草图 | 顶层草图行 → 编辑 / 删除 | 同上 |
| 实体的外观 | 右键 → 设置贴图；或外观区 | `SolidAppearance` |
| 实体本身 | 右键 → 删除 | 连同它的碰撞刚体一起清 |

⚠ **语义要点**：改草图会**连带影响**引用它的所有特征（几何是现算的）。
这正确，但**必须在 UI 上说清**：进"编辑草图"时提示"该草图被 N 个特征使用"，
否则玩家改完发现别的地方也变了，会以为是 bug。

## 5. 实现顺序（每步都可独立验证）

1. **只改树的构造**：`ModelUi` 里把被引用的草图从顶层移到对应特征下。
   判据用现成的 `SolidData.ofBody(...).sketchId`。**不动数据模型**，风险最低。
2. 展开/折叠状态用 `特征id + 草图id` 作 key。
3. 特征节点单击 → 左栏显示"该特征的参数"（复用已有的拉伸/旋转控件，把目标从
   "当前选中草图"改成"当前选中特征"）。
4. 草图节点的"编辑草图"入口 + "被 N 个特征使用"的提示。
5. 外观区（我们的 Display Manager）+ 右键"设置贴图"。
6. （暂不做）回滚条 / 特征重排序 —— 我们的几何是现算的，没有"历史重算"的概念，
   回滚条在这里没有对应的语义，硬做只会误导。
