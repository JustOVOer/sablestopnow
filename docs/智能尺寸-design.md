# 草图「智能尺寸 Smart Dimension」设计与实现

> 状态：**已实现，离线门禁全绿**（全量 `tools/verify-all.ps1` PASS）。
> 交互与显示按用户提供的 4 张 SolidWorks 截图（线段长度 / 线线距离 / 圆直径 / 点点距离）逐条对齐。
> 实机确认由用户完成（见 §7）。

---

## 1. 目标与范围

在 `com.ovo.sablestopnow.sketch` 与草图 UI 中实现 SolidWorks 式的智能尺寸，并遵守项目既有的
**GUI 统一化准则**：所有界面一律走 `client/gui/lib` 统一 GUI 库；文字与布局必须过 `UiLint`
全覆盖判据（不遮盖、不越界、有自动短标签 / 自动缩字号 / 自动换行）。

## 2. 求解器底座（ezpz）

- 上游：`ezpz`（Rust 几何约束求解器，MIT / KittyCAD）。
- 我们**自己的** C-ABI shim：`tools/ezpz-wasm`（本仓库跟踪；只忽略 `target/`）。它把上游的约束类型
  打成扁平 i32 程序 + f64 常量表，Java 侧用 JNA 调用（`SketchSolver`）。
- **ABI = 4，kind 1–25**。每次增删 kind 必须五处同步：文档表、`operand_count`、`takes_const`、
  `match` 分支、Java 侧常量与 builder —— 漏一处就会"静默算错"而不是报错。
- 运行期加载：优先 `<gamedir>/sablestopnow-natives/` 手动放入的 DLL，其次 classpath 资源；
  缺失时**不报错**，只是碰撞特性关闭（不影响 Sable 本体）。DLL 不随仓库分发（版权）。

### 2.1 关键实测结论（务必记住）

| 结论 | 含义 |
|---|---|
| `ConstraintRequest::highest_priority` 会**合流同几何同种约束** | 重复标同一个长度**不会报冲突**，而是静默合并 ⇒ **过定义必须由 Java 侧拦** |
| 冲突的**不同种**约束能被检测 | 例如同两点既定 4 又定 9 ⇒ `unsatisfied=2` |
| `parallel_lines_distance` 返回 `[Self; 2]` | shim 里对 kind 14 要**提前分支**（推两个约束再 continue） |

## 3. 「类推」组合出的尺寸类型

上游只有基本约束，所以：

- **线线距离** = 线线平行 + 一线上的点到另一线的距离（直接用上游 `parallel_lines_distance`）。
- 其余同法推导并落地到 Java builder：点线垂距 / 点线水平距 / 点线竖直距 / 两线平行距离 /
  水平距离 / 竖直距离 / 对称 / 等标量 / 弧半径 / 弧长 / 弧张角 / **两线夹角** / 线圆相切 /
  两圆相切 / 三点夹角。

## 4. 选择上下文驱动的类型推断

| 选择 | 推断 | 后备候选（左栏 / 右键循环） |
|---|---|---|
| 单直线 | 长度 | 水平 / 竖直 |
| 两直线 | 平行 ⇒ 线线距离；不平行 ⇒ **夹角** | — |
| 圆 / 圆弧 | 半径 | **直径** |
| 点 + 直线 | 点到直线的**垂距** | 水平分量 / 竖直分量 |
| 两点 | 两点距离 | 水平 / 竖直 |

- `SketchMeasure.variants(...)` 给出候选；`preview(...)` 按指针方位**自动捕捉**方位
  （dx > 2dy ⇒ 水平；dy > 2dx ⇒ 竖直；否则按当前类型，默认平行/对齐）。
- **过定义拦截**：`SketchSession.dimensionWith(kind, value, vars)` 先找同 kind 同操作数的既有约束
  —— 有则**改值**，无则新增；求解由调用方 `MODE.solve()` 负责。放置成功后清空选择（尺寸链模式除外）。
- **已知限制（如实记录）**：`EntityKind.ARC` 只有 `cx cy r a0 a1`，没有独立的起点/终点变量
  ⇒ 弧长与弧张角**只能作参考（从动）尺寸**，无法驱动几何。

## 5. 交互（用户确认的语义）

```
① 先开「智能尺寸」工具
② 点图元 ⇒ 加入选择（最多两个）—— 不是放置
③ 点空白 ⇒ 用当前选择放置尺寸，并在鼠标位置弹出 Modify 框
      · 框弹出后固定不动（输入控件不能跟随指针，否则无法打字）
      · 值已预选；Enter 应用；Esc 取消
④ 双击已放置尺寸 ⇒ 同样弹出 Modify 框 ⇒ 改值实时驱动几何
⑤ 按住尺寸数字拖动 ⇒ 移动标签（画与命中共用同一落点）
⑥ 右键 ⇒ 循环锁定候选方位（预览变实 + 锁定环）
⑦ 「尺寸链」开 ⇒ 放置后**保留基准选择** ⇒ 基准到后续图元依次成链
```

### 5.1 关于"光标变化"（需求 (4)）

SolidWorks 悬停到可标注实体时会把指针换成**标注光标**。我们**不改系统指针**（GLFW 指针由 Minecraft
每帧接管，强改会闪烁甚至消失），而是在**指针本体位置**画一个**准星**（十字角标）作为等价视觉标记：
锁定候选时准星变实、未锁定时半透明 —— 与"光标随状态变化"的语义一致，且零风险。
> 反面教训（值得留档）：早期版本在②就直接放置，导致**永远选不中第二个图元**，
> 两图元尺寸（线线距离/夹角）完全走不通。

## 6. 显示规则（对照 4 张参考图）

| 要素 | 规则 |
|---|---|
| 箭头 | **开放式 V 形**（两条短线成 V），不是实心圆点 |
| 尺寸线 | 段长足够 ⇒ **在文字处断开**（左段 + 文字 + 右段）；太短 ⇒ 整条画，文字沿尺寸线方向**外移** |
| 界线 | 与几何留 **4px** 缝，并**超出**尺寸线 **6px** |
| 线线距离 | **不画界线**（两条线自身即基准） |
| 圆 / 弧 | 参考点取**上下极值** ⇒ 界线水平引出、尺寸线竖直、标签在圆**外侧** |
| 颜色 | 驱动 = 深色（正常 0xFFE6E6E6）；从动/参考 = 灰 0xFF8C93A8 **并加括号**；实测≠常数时橙色提示未算平 |
| 上限 | 同屏最多绘制 48 条，避免糊屏与撑爆 GUI 批次 |

## 7. 如何验证

```
# 开发中：只跑受影响的块（不要动不动跑全量）
powershell -File tools/verify-all.ps1 -Only sketch     # 改 sketch 包内文件必须跑这个，见下
powershell -File tools/verify-all.ps1 -Only guispec
powershell -File tools/verify-all.ps1 -Only types
# 阶段收尾：跑全量
powershell -File tools/verify-all.ps1
```

- `-Only` **只接受单个块名**（传逗号列表会退化成只跑无守卫块）。
- **重要**：`com.ovo.sablestopnow.sketch` 包内的文件被 `tools/*Check.java` 离线 harness **单独编译**，
  任何对模组其它类（如 `SablestopNow.LOGGER`）的引用都会让 4 个 harness 编译失败，
  而 `types`/`guispec` 等块**不会发现**。日志与 UI 依赖一律放模组侧（`ModelUi`/`SketchClient`/`SketchHud`）。
- 实机排查用的两行日志：
  - `[sketch] tool=…`（工具是否切过去；在模组侧打印）
  - `[sketch-dim] click: hit=… selection=N entities=N constraints=N`
    （`constraints=N` 能一次分清"约束没落进数据"与"画不出来"）
- 界面自检：游戏内按 **F9** ⇒ 生成 `run/ui-lint.txt`（逐控件矩形、文字是否放下、有无遮盖/越界）。

## 8. 工程教训（本项目通用）

1. **新增 `switch(enum)` / 内部类后要清一次 `build/classes`**，否则会
   `NoClassDefFoundError: Xxx$1`（合成类没重新生成）。见 `.dshwolf/buglog.json`。
2. 改文件**先读该区域原文**，再做**带边界断言的按行替换**；字符串替换在缩进/同名行/换行上极易出事。
3. 「必须失败的合成用例」是判据的护栏：曾试图放宽 0 尺寸检查 ⇒ 自检立刻变红 ⇒ 回退。
   宁可日志多两条已知噪声，也不让判据变弱。
4. 已知无害噪声：手工布局的 HUD 面板（`UiLayer.size(0,0)` + 自己排位置）会触发
   "可见但尺寸为 0" 的告警（`Callout#null` / `Container#null`）—— 设计如此，非缺陷。
