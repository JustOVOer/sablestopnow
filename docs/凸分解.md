# 凸分解：让非凸 / 带孔的形状真正能碰（2026-10-03）

> **一句话**：碰撞体只能是**凸**的 ✗，所以以前给每个实体挂的那个**单凸包**会把
> **孔**（垫圈 / 窗框 / 圆环）和**凹口**（L 形）**整个填掉** ✗ ——
> 表现就是"**明明看着是空的，却撞墙**"✓，而且**穿不过去** ✓。
> 现在按形状的**发生器**做**精确**凸分解 ✓，一个实体挂**多块**凸包 ✓，**孔保持是空的** ✓✓。

---

## 1. 为什么不用通用网格凸分解（VHACD 那一类）

我们的几何**不是随便一份三角网格** ✓ —— 它由两种发生器产生 ✓：

| 成形方式 | 参数空间里的形状 |
|---|---|
| `Extrusion` | 一个平面轮廓（`SketchProfiles.Region`，**孔是显式字段** ✓）沿法线拉伸 |
| `Revolution` | 同一个轮廓绕平面内的一条轴旋转 |

⇒ **在参数空间里分解是精确的** ✓✓，而通用网格分解只能给**近似** ✗，
而且它要么算在原生侧（没法离线断言 ✗ 这个项目已经因此吃过亏 ✗），
要么得从三角网格里把**孔重新猜出来** ✗ —— 而我们的孔本来就写在数据里 ✓。

**⇒ 结论：分解放在纯 Java 里，用形状自己的结构做 ✓。**

## 2. 算法

```
拉伸：区域（外环 + 孔）
      → SketchProfiles.triangulate（**已经会正确桥接孔** ✓）
      → 贪心合并相邻三角形（**每次取合并后面积最大的一对** ✓）
        合并必须同时满足三条：① 面积守恒 ② 每个顶点都凸 ③ 不自交
      → 若干【凸多边形】→ 每个沿法线拉伸 = 一个【凸棱柱】✓

回转：同一个 2D 分解作用在【子午线】上 ✓ → 每块再按角度切扇区 ✓
      · 子午线【贴轴】（球 / 圆锥 / 圆柱）⇒ 整圈扫出来仍是凸的 ✓ ⇒ **1 块** ✓
        （= 与加本功能之前完全一致 ✓ 无回归 ✓）
      · 子午线【离轴】（圆环 / 垫圈 / 管子）⇒ 必须切扇区 ✗
        否则整圈的凸包会把孔填掉 ✗✓（这正是要修的现象 ✓）
      · 扇区数按**弓高 ≤ 0.15 格**算 ✓ 上限 16 ✓
```

**三条合并判据缺一不可** ✗（都是实测补上的 ✓）：

| 判据 | 挡住什么 |
|---|---|
| **面积守恒**（合并后 = 两块之和 ✓） | 合并出重叠 / 漏掉一块 ✗ |
| **逐个顶点凸性** ✓（不是只查接缝两端 ✗） | **吃进孔** ✗ —— 孔的边界点在"材料在左"的环里是**凹顶点** ✗，只有逐点查才挡得住 ✓✓ |
| **不自交** ✓（严格相交 ✓ 顶点贴边不算 ✓） | 蝴蝶结形的假凸多边形 ✗（它的鞋带面积与真实面积无关 ✗） |

## 4. 为什么圆环**必须**降采样（这条最反直觉 ✗→✓）

要求"孔一块都不许碰" ✓ 时，**每块只能含很短的一段内弧** ✗：
内弧对这块来说是**凹的** ✗ ⇒ 一旦跨得长，合并出来的多边形就不凸 ✓ 被拒 ✓。
⇒ 块数 ≈ **内圈的分段数** ✗ —— 实测 48 段 ⇒ **48 块** ✗✗。

压块数的**正确**办法不是放松"孔不许碰" ✗（那正是本次要修的东西 ✗），
而是**把曲面本身画粗一点** ✓：

```
16 段 ⇒ 每段内缘是一条【直边】✓ ⇒ 一块能盖住更长的一段 ✓ ⇒ 17 块 ✓
而且孔依旧是【精确】的 ✓ —— 块的边界就是内多边形的边 ✓ 一点没往里啃 ✓
```
代价：曲面的碰撞比画面**略糙** ✓（内接多面体 ✓ **永远往内** ✓ 不会鼓出去 ✗）。
这与项目自己那套 `Sampling.COLLISION` 的取舍是同一个道理 ✓。

**⇒ 实现是"采样精度阶梯"** ✓：从"和网格一致（48 段）"开始试 ✓，
块数超预算就换更粗的一档（24 / 16 / 8 段 ✓），
全部超预算才放弃 ✓ 并**退回单个凸包** ✓（= 旧行为 ✓ 至少不会没有碰撞 ✓）。

## 5. 两个**只有离线断言**才能抓到的 bug ✗✓（已写进代码注释 ✓）

### ① 顶点哈希碰撞 ✗✗
第一版的去重键是 `qx·C1 ^ qy·C2` ✓，而且**查到时从不核对坐标** ✗。
实测 `(2.9743, −0.3916)` 与 `(−2.9743, +0.3916)`（关于原点对称 ✗）**撞成同一个点** ✗
⇒ 三角化的拓扑被打乱 ✗ ⇒ 半径 3 的**圆（本来就是凸的 ✓ 应该合成 1 块）被拆成
11 块互相重叠的多边形** ✗，面积之和 = 净面积的 **3.06 倍** ✗✓。

> **⇒ 规则：哈希键只能用来分桶，相等必须靠键本身** ✓。
> 现在桶里逐个比量化坐标 ✓ ⇒ 碰撞只是多比较几次 ✓ 不再改变结果 ✓。

### ② 贪心顺序 ✗
原来"扫到第一个能合的就合"✓ ⇒ 圆环 48 块 ✗。
改成**最优优先（合并后面积最大）** ✓ ⇒ 同样的判据下块数明显下降 ✓。

## 5.1 ⚠ 碰撞**不会自己回来** ✗✓ —— 重开存档必须自愈（2026-10-03 实测）

`SolidCollisionService.rebuild` 原来**只**被"玩家保存草图 / 保存实体"的网络包调用 ✗，
**没有任何"世界加载 / 玩家进服"的补建** ✗✓。于是重开存档之后：

| 现象 | 原因 |
|---|---|
| 曲面实体**完全没有碰撞** ✗ | 凸包根本没挂上去 ✓（日志里一条 `凸分解` 都没有 ✓）|
| 手感**「质量不足」** ✗ | 质量是在**挂载那一刻**记进 `PARTS_BY_BODY` 的 ✓ ⇒ 不重建就没有那一条 ✓ |

**修法**：`SolidCollisionService.ensureCollisions(level)` ✓ ——
`onServerTick` 每 20 tick 扫一次 ✓，**结构已加载**就补建一次 ✓（补过就跳过 ✓）；
结构**没**加载时**不标记**成已处理 ✓（否则它永远补不上 ✗✓）。

**日志**：补建时会打
```
[sablestopnow] 碰撞自愈: body=… 的实体碰撞已补建 ✓
```
⇒ **排查口诀**：进世界后**一条 `凸分解` / `碰撞自愈` 都没有** ⇒ 就是这条路没走 ✓。

## 7.1 这条路**只管曲面** —— 直边形状走的是箱子分解 ✓（重要 ✗→✓）
`SolidCollisionService` 的路由是："**回转体** ∨ **轮廓有曲率** ⇒ 凸包路" ✓，
其它（矩形 / L / 方框这类**直边**轮廓）走**扫描线盒子分解** ✓ ——
而那套对直边形状本来就是**精确**的 ✓（盒子也是最少的 ✓），所以**不需要**改 ✓。

⇒ **本功能修的是"曲面 + 非凸"** ✓：圆环 / 垫圈 / 管子 / 带孔的旋转体 ✓，
以及**多个分离区域**（以前会被一个凸包连起来 ✗）。

> ⚠ 由此也能推出一个**排查口诀** ✓：**如果坏的是直边形状 ⇒ 别看这里** ✗，
> 去看 `SolidCollision` 的盒子分解 ✓；坏的是曲面 ⇒ 看这里 ✓。
