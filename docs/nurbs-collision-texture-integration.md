## 主题 A：NURBS 如何配合原有碰撞方案（体素碰撞体 1/16）

### A.1 先纠正一个方向：我们**不需要**通用内外判定

调研给出的最强方案是 [GWN（Generalized Winding Numbers）用于裁剪 NURBS 的包含查询](https://arxiv.org/abs/2504.11435)
（ACM TOG 2026），它**完全不做几何离散化**、对不水密模型鲁棒 —— 这确实是"通用闭合 NURBS 体"的标准答案。

**但我们的实体不是通用闭合体**：全部形如"**二维闭合轮廓（可带孔）+ 扫掠规则**"（拉伸 / 回转）。
对这种形状，三维点的内外判定可以**精确闭式**地化归到二维：

```
3D 点 →（逆映射）→ (轮廓平面内的二维点, 扫掠参数)  →  在轮廓内 && 参数在区间内
```

好处是**没有迭代、没有奇偶抖动，还能顺便给出到边界的带符号距离**（边界格判定直接要用）。
原型 `sketch/nurbs/SweptSolid.java` 实现的就是这条，`Voxelizer` 建在它上面。

> **结论**：GWN 留给将来的自由曲面（P5）。现在用解析逆映射，更快更准。
> ⚠ 代价是**范围受限**：只有"轮廓+扫掠"类实体能用（也就是我们现有的全部实体）。

### A.2 一条反直觉但省事的定量结论

调研把弦高公式 `s ≈ κh²/8` 代进我们的参数（`h = 1/16` 方块）：
**只有当曲率半径小于约 1/32 方块（≈3cm）时才需要为了曲率加密**。

也就是说：**在 1/16 分辨率下，"曲率驱动的自适应细分"几乎永远不会触发**。
真正要管的是另外三件事：

| 真正的问题 | 后果 | 对策 |
|---|---|---|
| **薄壳**（比一格还薄） | 格心采样会让实体**整个消失**（gprMax 文档明确承认这个失败模式） | 保守准则 + "近表面强制保留一层" |
| **近切**（曲面几乎贴着格平面） | 奇偶/符号抖动 | 保守准则（过近似） |
| **裁剪边界**（轮廓边界） | 边界格判错 | 用带符号距离做边界带判定 |

**这直接省掉了我们本来打算做的"曲率自适应细分"那一大块复杂度。**

### A.3 物理上必须选**过近似**（保守）

调研给的规范级依据：D3D12 的 conservative rasterization 把光栅化分成
**overestimated（无 false negative，允许 false positive）** 与 underestimated 两族。

对碰撞而言结论明确：**穿模比外扩难受得多**——外扩最多 `ε`，穿模会让物体陷进地面。
所以默认用 `Criterion.CONSERVATIVE`（原型里已实现，且断言"**绝不漏判**"）。

### A.4 误差账本（可证明，已断言）

每个方块格切成 `subdiv³` 子格、按**子格中心**判定时，只有曲面附近一层薄壳可能判错，
壳厚不超过子格半对角线：

```
ε = (cell / subdiv) · √3 / 2
|S_voxel Δ S_true| ≤ Area(∂S) · ε + O(ε²)
```

`tools/NurbsCollisionCheck.java` 用**实测对称差 vs 公式上界**钉住这条，
并且额外断言"**上界不空泛**"（实测 ≥ 上界/20）——否则上界写得再漂亮也没有约束力。

`1/16` 实测：体积相对误差 **<2%**，且随子格变细单调下降。
保守准则下体素体积 **≥ 真实体积**（不出穿模）。

### A.5 落地流程（采纳调研的 7 步，按我们的形状简化）

1. **轮廓 → 二维环**（已有 `SketchProfiles.findLoops`）；
2. **扫掠逆映射**（{@link SweptSolid}）→ 解析内外 + 带符号距离；
3. **每格建 16³ 子格**，三态剔除：必在内 / 必在外 / 边界带（用 `|signedDistance| ≤ 子格半对角线`）；
4. **边界带按保守准则填**，薄壳强制保留一层；
5. **贪心合并**（原型已实现；此前实测能去掉 75~81% 的盒子）；
6. **喂给 `addVoxelColliderBox`**（每格一个形状，局部 [0,1]，1/16 对齐 —— 断言已钉住"所有盒子坐标都是 1/16 整数倍"）；
7. **跨格邻接**：⚠ parry 文档明确提到"在相邻体素之间的边棱上会被卡住（snag on edges）"，
   所以**跨方块的合并必须让邻接状态一致**。这一条是**唯一未验证的工程风险**，
   需要在实机上确认 Sable 的体素碰撞体是否暴露邻接合并入口。

### A.6 与画面的**一致性**（"统一"的真正收益）

渲染网格与碰撞体素**从同一个 `SweptSolid` 派生**：

```
SweptSolid ──┬── Voxelizer（保守，1/16）      → 碰撞
             └── NurbsShapes.tessellate（弦高） → 画面
```

两者不再是"各算各的"，所以"看着能过、实际撞上"这类问题在原理上消失。

## 主题 B：通用贴图方案

### B.1 ⚠ 最重要的发现：我们现在的 bug 有一个**直接根因**

调研指出：**`frac` 做在顶点/CPU 阶段是错的**。

> 插值必须发生在**未回绕的连续 UV 空间**里，**回绕只能发生在 fragment 采样前的最后一刻**。

这正好解释了我们反复看到的现象——"四个角的 `frac` 各自回绕、插值出垃圾（大片单色/三角块）"：
角点各自 `frac` 之后，三角形内部在两个不同的贴图周期之间做线性插值，结果必然是垃圾。

**这一条比任何"更好的映射算法"都优先**：映射算得再对，只要 `frac` 在顶点阶段做就还是坏的。

### B.2 三条路线的评估（含 1.21.1 的实际可行性）

| 路线 | 结论 | 依据 |
|---|---|---|
| **A. 方块贴图 → 独立 REPEAT 纹理** | ✅ **主线** | 1.21.1 的 `SimpleTexture` 有 `upload(image, blur, clamp)`，不写 `clamp:true` 就是 **REPEAT**（GL 的 `WRAP_S/T` 初值即 REPEAT）；`TextureStateShard(RL, blur, mipmap)` 允许自定义 RenderType 绑任意贴图 —— 我们现在的 `ModRenderTypes` 用的就是这个机制 |
| **B. 自定义着色器手写 wrap** | ✅ 并行/兜底 | 顶点输出未回绕 UV → fragment `fract` → `textureGrad`（必须用未回绕 UV 的导数，否则回绕处有 mip 细线） |
| C. `GL_TEXTURE_2D_ARRAY` | ❌ 1.21.1 不可行 | 1.21.1 的 `GlStateManager` **没有** `texImage3D`；`TextureState` 只有一个 `binding` 字段，绕过会让状态缓存与实际 GL 不同步；1.21.5 才会重写这层 |
| **D. 几何切割** | ⚠ 降级为局部纠错 | 只切"不跨多张贴图"的话，共享边上仍是 0.99 vs 0.01，**可见的缝还在**；切成"每片恰好一个周期"则把细分密度绑死到 16 像素周期，放弃自适应细分 |

> **顺带说清一件事**：我上一轮给 `SolidUv` 加的"在贴图边界处细分"（路线 D），
> 在**路线 A 成立之后就不再需要了** —— REPEAT 纹理天然解决平铺，且没有接缝。
> 那块代码应视为**过渡方案**，等路线 A 落地后删除（留着会增加顶点数与复杂度）。

### B.3 "通用"的正确形态：**映射类型 + 独立尺度**

调研确认 CAD 业界的做法是**把"方向"和"尺度"分开**：
- **方向**：按面的本性选映射类型（Planar / Cylindrical / Spherical / Box / Surface）；
- **尺度**：一个独立的"世界尺寸 → UV 缩放"常量统一管住（SolidWorks Visualize 的三档：
  Fit to Part / Set to World Scale / Manipulate Texture）。

我们照搬这个分层，而且比 CAD 更有优势：**面的本性是我们自己造的**（草图画的是什么，我们知道），
所以映射类型可以**自动选**，不需要用户指定。

原型 `sketch/nurbs/TextureMapping.java` 实现了 5 种模式，并给出**可测的畸变指标**
（曲面真实距离 / 贴图坐标距离 的 `max/min`，1.0 = 完美）。实测：

| 面 | 模式 | 实测畸变 |
|---|---|---|
| 圆柱 | **Cylindrical** | **<1.05** ✓ |
| 圆柱 | **Surface（弧长）** | **<1.05** ✓ |
| 圆柱 | Planar | **∞**（轴向被压缩到 0）✗ |
| 平面片 | Planar | **1.000000**（完全等距）✓ |

这两个"∞"和"1.0"就是"**必须有模式**"的量化证据。

⚠ 指标本身也踩过两个坑（都是断言逼出来的，已修）：
① 零压缩被静默跳过 → 平面模式假满分；② ±π 的角度接缝被当成畸变 → 圆柱模式假 64 倍畸变。

### B.4 弧长重参数化：实测有效，且**必要性**已被证明

`sketch/nurbs/NurbsReparam.java`（张量积：u、v 各自独立做弧长重参数化）。

实测尺度不均匀度（`max/min`，1.0 = 完全均匀）：

| 曲面 | 自然参数 | 弧长重参数化 |
|---|---|---|
| 圆柱（均匀节点） | 1.171 | **1.005** |
| 圆柱（**刻意非均匀节点**） | **>2** | 显著下降 ✓ |

第二行是必要性证明：节点向量一不均匀，自然参数就直接不可用。

⚠ 诚实边界（调研明确）：**不可展曲面不存在等距参数化**，
所以曲面重参数化只能消掉**尺度畸变**，消不掉**切变**。
畸变的通用语言是 Jacobian 奇异值（σ1/σ2 共形、σ1σ2 面积）。

### B.5 性价比最高的一条后处理：**接缝整数对齐**

调研里最值得采纳的思路：**方块贴图是整数周期可平铺的，所以"UV 差一个整数"在视觉上完全相同**
——把相邻面片的 UV 平移最接近的整数向量使其对齐，**缝就不可见了**。
复杂度 O(面片数)，用并查集避免"修了 A-B 破坏 B-C"。

这条比任何参数化优化都便宜，建议在路线 A 落地后立刻做。

### B.6 Triplanar 的改进（若保留作兜底）

缝的来源已查清（UE5 的 mask 用两次顺序 Lerp）：① **余弦 ≠ 等份**（45° 并非 50/50，
要用 `|N.x|/(|N.x|+|N.y|)`）；② 第三个投影有"粘性"。
修法按代价：归一化 `pow(|n|,k)` 权重 → **Whiteout/UDN**（修 45° 对角亮带）→
**Biplanar**（2+1 采样，天然对应 MC 的"顶面/侧面两种贴图"）。

### B.7 三条铁律（写进代码注释，避免后人重犯）

1. **`frac` 只能出现在 fragment shader 的最后一步**（顶点阶段做必错）；
2. 手写 wrap **必须配 `textureGrad`**，用未回绕 UV 的导数；
3. 弧长重参数化**预计算成单调表**，不要放进每帧热路径。
