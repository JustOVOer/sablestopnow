# 模型布尔运算 —— 调研（Aspose.3D FOSS vs 第三方 CSG）

> 状态：**调研完成，方案待定**（用户要求"暂缓实现，先研究；更倾向用第三方库"）。
> 结论先说：**`depends/Aspose.3D-FOSS-for-Java-main` 做不了布尔** —— 布尔 API 全是桩。

---

## 1. Aspose.3D-FOSS：布尔是桩，不能用

在 `depends/Aspose.3D-FOSS-for-Java-main.zip` 里逐处核对（源码为准，非文档）：

### 1.1 `Mesh` 的布尔 API 全部"原样返回 a"

```java
public static Mesh union(Mesh a, Mesh b)      { return a.clone(); }
public static Mesh difference(Mesh a, Mesh b) { return a.clone(); }
public static Mesh intersect(Mesh a, Mesh b)  { return a.clone(); }
public static Mesh doBoolean(BooleanOperation op, Mesh a, Matrix4 ma, Mesh b, Matrix4 mb) {
    return a.clone();   // ← 什么都没算
}
```

### 1.2 `BooleanOperator.toMesh()` 返回 `null`

```java
public Mesh toMesh() {
    return null;
}
```

### 1.3 `BooleanOperand.of(mesh, transform)` 把 transform 丢了

```java
public static BooleanOperand of(Entity mesh, Matrix4 transform) {
    return new BooleanOperand(mesh);   // transform 没保存
}
```

### 1.4 项目自称"未完成的移植"

- `TODO.md`：`PolygonModifier.java has incorrect implementation` / `PolygonModifier.java must be removed - incorrect implementation`

## 2. Aspose.3D **商业版**确实支持布尔（但要授权）

- [Aspose.3D for Java 23.10](https://releases.aspose.com/3d/java/23-10-0/)：新增 **Boolean Mesh Operations**（manifold 几何的并/差/交）
- [Aspose.3D for Java 25.3](https://releases.aspose.com/3d/java/25-3-0/)：新增 **Boolean Modeling 与 B-Rep 支持**

⇒ 能力是有的，但需要商业授权，且与我们"离线/开源构建"的现状冲突（CI、分发都要考虑许可证）。可作为"以后愿意买授权"的备选。

## 3. 可用的第三方 CSG 库（Java，Maven）

| 库 | 特点 | 坐标 |
| --- | --- | --- |
| **JCSG** | BSP 树实现的 CSG（并/差/交），纯 Java、无原生依赖；经典方案，API 简单（`CSG.union/difference/intersect`） | `eu.mihosoft.vrl.jcsg:jcsg`（具体版本需在 Maven Central 确认） |
| **java-csg** | JCSG 的活跃分支/重写（micycle1），改进鲁棒性 | 见 GitHub `micycle1/java-csg` |

两者都是**三角网格 → BSP → 结果网格**：
- 优点：真·网格布尔，渲染结果精确、能出孔洞与内壁
- 缺点：① 只产出**网格**，不产出我们的**碰撞盒子**（物理只吃盒子）；② BSP 对共面/退化面敏感，需要清理；③ 结果三角形数会涨

## 4. 与现有架构怎么接

我们的实体管线：`Extrude.boxesOf`（轮廓 → 轴对齐盒子）+ `SolidMesh`（渲染网格）+ `SolidCollision`（有向盒碰撞）。

物理（Sable/Rapier）**只能吃盒子** ⇒ 所以布尔必然有两条线：

1. **碰撞侧**：必须做**盒子/体素层**的减法（已经在做：`Solid.subtractBoxes`）
2. **渲染侧**：可选
   - 现状（v1，已实现）：三角形按**重心落在切割盒内**剔除 ⇒ 洞看得见、贴图还在，但边界有毛边
   - 升级（第三方库）：把目标网格与切割网格交给 JCSG 求差 ⇒ 精确孔洞与内壁

替换点很干净：`Solid.clipMesh(mesh, cutters)` 换成 `CsgAdapter.difference(targetMesh, cutterMesh)`，其余（盒子减法、序列化、UI 开关）都不用动。

## 5. 建议

**推荐路径（分两步）**
1. **先保留现有盒子层实现**（已能用：碰撞上是真打洞；渲染上洞可见）——不阻塞验收
2. **渲染侧引入 JCSG**：新增 `depends/jcsg.jar`（或 Maven 坐标）+ 一个 `CsgAdapter`，把 `clipMesh` 换成真布尔；碰撞侧继续用盒子减法（因为物理只吃盒子）

**不推荐**
- 用 Aspose.3D FOSS（布尔是桩，零价值）
- 买 Aspose 商业版（除非确实要 B-Rep/STEP 级能力）
