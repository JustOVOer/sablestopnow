## 1. 圆弧改为"两条辅助线派生"

### 目标
圆弧不再是独立存 6 个变量的图元，而是**由两条辅助线生成的产物**：
- 线 A：圆心 → 起点
- 线 B：圆心 → 终点
- 两条线**共享圆心的变量下标**（结构上就是"一端重合"，**不额外加重合约束**）
- 两条线之间加 **EQUAL_LEN（等长）** 约束

这样自由度正好是 5（圆心 2 + 半径 1 + 两个角度 2），**不会过定义**（用户提出的担心）。

### 绘制方式
与现在**完全相同**的三次点击（圆心 → 起点 → 终点），只是画完额外生成两条辅助线，并把弧登记为派生图元。

### 数据表示
- 两条线是**真图元**（`EntityKind.LINE`），带 `construction` 标记。
- 圆弧是**派生图元**：复用两条线的变量下标（`{Cx,Cy,Sx,Sy,Ex,Ey}`，其中 `Cx,Cy` 是两条线共用的），**不新分配变量**。
- 方向位 `cw`（现有 `Entity.cw()`）保留，决定"劣弧往哪一侧"。

### 随之要改的
- 半径 = 线长（`EQUAL_LEN` 保证两条线等长，所以半径只有一个值）
- 弧角 = 两条线的夹角
- 弧长 = 半径 × 夹角
- `Sketch.arcSweep / arcPoint / arcRadius / arcStart / arcEnd / arcEndpoints` 改为基于上述表示
- 相切、轮廓焊接、碰撞仍然认"弧"这个概念（派生图元也要被 `entities()` 看到，或者提供一个"派生图元列表"给轮廓用）

### 兼容
- 读旧存档时：遇到旧 ARC（自己带 6 个变量）⇒ **自动补两条辅助线**并转成新表示。

### 顺带修
- **辅助线画成虚线**：现在世界渲染层仍按实线画（`SketchRenderer`），HUD 那层虚线（`drawConstructionOverlay`）不够。改成：**世界渲染时对 construction 图元直接画虚线**，HUD 那层去掉或只保留端点提示。

## 2. 直线尺寸的三分类判定

### 判定（顺序很重要）
设线 A→B，单位方向 `d`，法向 `n`，长度 `L=|AB|`，指针 P：
1. `s = (P−A)·d`
2. **`0 ≤ s ≤ L` ⇒ 距离**（对齐尺寸；即"两端点垂线之间"的无限长带）
3. 否则取**最近端点**，令 `dx = |P.x − E.x|`、`dy = |P.y − E.y|`：
   - `dx > dy` ⇒ **水平**
   - 否则 ⇒ **竖直**
   （这就是"剩余区域按 45° 界线划分"，界线按**坐标轴**）

### 显示（预览与正式必须一致）
- **距离**：尺寸界线**垂直于该直线**（现有样式）
- **水平**：尺寸界线**竖直**（平行于网格）
- **竖直**：尺寸界线**水平**（平行于网格）
- 预览与落下后使用**同一套**计算（禁止两处各算一次 —— 本项目已多次栽在这上面）

## 3. 贝塞尔曲线（三次）

### 入口
与其他图元并列（左栏图元工具区新增"贝塞尔"）。

### 点击顺序（4 次）
1. `P0` = 手柄 1 起点（曲线起点）
2. `C1` = 手柄 1 终点（控制点 1）
3. `P3` = 手柄 2 起点（曲线终点）
4. `C2` = 手柄 2 终点（控制点 2）

- 落下第 3 点后要有**预览**（P0→C1→C2→P3 的曲线预览）。
- 手柄 1 = 普通辅助线 `P0→C1`；手柄 2 = 普通辅助线 `P3→C2`。
- 曲线 = 三次贝塞尔：`B(t) = (1−t)³P0 + 3(1−t)²t·C1 + 3(1−t)t²·C2 + t³P3`。

### 数据表示
- 手柄是 `LINE` + `construction` 标记，是真图元。
- 曲线是**派生图元**（引用 4 个控制点的变量），不新分配变量（与圆弧同一思路）。

### 功能
- **参与轮廓**：贝塞尔要能成为闭合边界的一部分 ⇒ 可拉伸、参与碰撞。
- 采样：按弧长或等参采样成折线（段数随曲率自适应，至少 24 段）。
- 端点吸附到已有几何（与直线一致）并落重合约束。

## 4. 草图常驻背景网格

- **网格线**：浅灰 `#C8C8C8`，**70% 不透明度**，细线（1px 等效）
- **背景填充**：浅灰 `#C8C8C8`，**20% 不透明度**
- 间距 **1 格**（= 1 方块）；范围固定 **60×60 格**（以草图原点为中心）
- 画在**草图平面上**（3D 中跟随平面，不是屏幕贴图）
- 常驻：进入草图即显示，不因工具/选择变化而消失
- 与现有"吸附格线提示"互不干扰

## 5. 切割台体（布尔）

### 结论：自己做，在**盒子分解层**做
理由：现有实体管线是 `Extrude`（轮廓 → 轴对齐盒子 + 侧面四边形）→ `SolidMesh`（渲染网格）/ `SolidCollision`（有向盒碰撞）/ `ConvexDecomposition`。盒子层做布尔是现成基础设施，稳、快、与碰撞天然一致；网格层真布尔既慢又易碎。

### 设计
- 新增 `Solid.Shape.Cut`（或给 `Extrusion` 加 `boolean cut` 标志）：记录"切割体"的拉伸参数 + 目标实体。
- 求值流程：目标实体的盒子集合 **减去** 切割体的盒子集合 ⇒ 得到新盒子集合 ⇒ 据此重建：渲染网格、碰撞、体积/质量、包围盒。
- 支持 **完全贯穿** 与 **给定深度** 两种。
- 切割对象：同一 body 内与该拉伸体**相交的所有实体**。
- 入口：**拉伸面板里切"新建/切割"模式**（切割模式下列出目标数量）。

### 实现要点
- 盒子减法：对每对 (目标盒, 切割盒) 做 AABB 差集，一个盒子最多切成 6 块，递归/迭代到稳定；结果去重并合并共面邻接（可选，性能）。
- 切割体的盒子由同一个 `Extrude.boxesOf` 生成，保证两侧一致。
- 网格重建：由结果盒子集合生成面（只在"外侧"生成面，避免内部面），再套用现有外观/贴图逻辑。
- 存档：切割关系要能序列化（`SolidData`）。
