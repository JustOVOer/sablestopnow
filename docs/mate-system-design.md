# 配合系统（SolidWorks 式 Mates）设计说明

> 对应 `cp/description.txt`（配合类型清单）与 `cp/GUI.png`（「物理结构 → 配合」树形界面 + 用图标标识类型）。
> 功能入口：手持物理手杖按 **Y** 进入配合模式；**M** 打开配合界面。

## 1. 一句话概括

一条配合 = **一个 Sable 6 轴通用关节的「锁定轴集合」** + **一次把 B 结构吸附到位的位姿修正**。

## 2. 为什么是这个形态

Sable 提供 `GenericConstraintConfiguration(pos1, pos2, orient1, orient2, lockedAxes)`，落到 rapier 上就是一个
通用关节：它把 **frame1（A 局部）** 与 **frame2（B 局部）** 拉到重合，`lockedAxes` 决定消掉哪些自由度。
这正好可以表达 SolidWorks 的各类配合，但有一个<b>关键限制</b>：

> **「锁定某个轴」的语义是该轴上的相对偏移归零**，所以它只能表达「等于装配时那个状态」，
> 表达不了「距离 3 格」「夹角 90°」。

于是系统的做法与 SolidWorks 一致：**先吸附、再零误差建关节**。

- 创建时：先算出 B 应该在哪（`MateFrames.solve`），`teleport` 过去并清零残余速度，然后建关节；
- 距离/相切这类非零偏移：不用 lock，改用 `GenericConstraintHandle.setLimit(axis, v, v)` 把该轴钉在目标值上；
- 关节失效后重建（`MateFrames.frames`）：**不再吸附**，按当前位姿重算坐标系。因为约束是相对参考点表达的，
  定义上不需要重新吸附；而重新吸附会在结构被外力推歪后突然把它拽回去。

## 3. 坐标系是怎么装配的（核心）

关节坐标系的两个 frame 必须**在吸附后的姿态下就已经重合**，否则一建出来就会互相拉扯。
做法是先在**世界系**里装配一个正交基 `W`，再取：

```
M1 = R_A⁻¹ · W      frame1 = (参考点A, M1)   落在 A 的 plot 局部
M2 = R_B⁻¹ · W      frame2 = (参考点B, M2)   落在 B 的 plot 局部
```

两者在世界系里都等于 `W`，零误差。锁定轴就落在这个 `W` 上，语义因此变得很直观：

| 锁定的轴 | 几何含义 |
|---|---|
| `ANGULAR_X`, `ANGULAR_Y` | 两侧基座只能绕共同 Z 相对转动 ⇒ **放在 Z 上的方向保持不变** |
| `LINEAR_Z` | 沿共同 Z 的相对偏移归零 |
| `LINEAR_X`, `LINEAR_Y` | 垂直于 Z 的平面内相对偏移归零 |

### 垂直配合为什么要换轴位

「两方向垂直」看起来没法用锁定轴表达（锁 `ANGULAR_X,Y` 得到的是**平行**）。绕法是：
**把 B 侧方向放在 frame2 的 X 轴上**（即令 `W.x = B 的方向`）。此时锁 `ANGULAR_X,Y` ⇒
`W.z` 两侧相等，而 `W.z ⟂ W.x`（正交基）⇒ **B 的方向恒垂直于 A 的方向**。

同理：
- 平行：两侧方向**都放在 Z 上** ⇒ 锁 `ANGULAR_X,Y` 后保持平行，绕轴自转自由；
- 角度 θ：让 `W.z = A 的方向`，吸附时把 B 转到与 A 成 θ；锁 `ANGULAR_X,Y` 后只允许绕 `W.z` 转动，
  而绕 `W.z` 转动**不改变方向的 Z 分量**，所以夹角 θ 被保持住。

## 4. 各标准配合的映射

| 类型 | 锁定轴 | 吸附（B 怎么动） |
|---|---|---|
| 锁定 Lock | 全部 6 轴 | **不动**（保持当前相对位姿；两侧 frame 原点取两点中点，否则关节会把参考点拉到一起） |
| 重合 Coincident（点—点） | `LINEAR_X,Y,Z` | 平移到两点重合 |
| 重合（点落在面上） | `LINEAR_Z` | 只消掉法向间隙 |
| 重合（面—面 / 基准面） | `LINEAR_Z` + `ANGULAR_X,Y` | 法线对齐（同向/反向）+ 共面；面内平移与自转自由 |
| 平行 Parallel | `ANGULAR_X,Y` | 方向对齐 |
| 垂直 Perpendicular | `ANGULAR_X,Y` | B 的方向转到垂直于 A（最小转动） |
| 同心 Concentric | `LINEAR_X,Y` + `ANGULAR_X,Y` | 轴线对齐 + 消掉垂直轴线的偏移；沿轴滑动与绕轴自转自由 |
| 相切 Tangent | `ANGULAR_X,Y` + `setLimit(LINEAR_Z, v, v)` | 方向对齐 + 沿法线放到指定间距 |
| 距离 Distance | `setLimit(LINEAR_Z, v, v)`（点—点则锁 3 个线性） | 沿法线放到指定距离 |
| 角度 Angle | `ANGULAR_X,Y` | B 的方向转到与 A 成 θ |

## 5. 参考几何（两端从哪来）

两类，都存**描述**而不是算好的世界坐标（结构会动、会被增删方块）：

- **方块级**（玩家视线选取）：`VERTEX` 角点 / `EDGE` 棱 / `FACE` 面。
  存 plot 局部的 `block` + `face`（命中面）+ `feature`（面内 0..3 的角点/棱序号）。
  分类是**就近判定**：命中点在面内的归一化坐标 `|u|,|v|` 都接近 0.5 → 角点，只有一个接近 → 棱，否则 → 面。
- **结构级**（包围盒派生）：`BODY_CENTER` 中心 / `BODY_AXIS` 主轴 X,Y,Z / `BODY_PLANE` 基准面 X,Y,Z。
  从 `plot.getBoundingBox()` 现算，因此结构被增删方块后依然有效。

**为什么命中点是 plot 局部坐标**：Sable 重写了 `level.clip` 并接受一个「位姿提供器」，射线是在物理结构的
渲染位姿下求交的，命中点直接就是 base（plot）坐标，命中面也是 plot 局部的面 —— 正好是 `MateRef` 要存的，
不需要世界↔局部来回换算，也不会因为结构旋转/缩放而选错格子。

## 6. 交互流程

1. 手持手杖按 **Y** → 客户端发 `MateModePayload(true)`，进入配合模式（服务端清空待选）。
2. 每帧 `MatePreviewRenderer` 重新求交，把**右键将会选中的那一端**渲染出来
   （角点=小方块、棱=线段+两端点、面=半透明面、结构基准=琥珀色）。
   预览与提交必须是同一份数据，否则玩家会看到「A 选中了 B」。
3. **右键**提交 → 服务端追加到待选；**Shift+右键**撤销上一端。
4. 待选凑满两端 → **自动推断配合类型**（两端都是轴类=同心，其余=重合）并尝试成配；
   冲突则拒绝并提示（待选保留，玩家可以撤销一端再试）。
5. 成功 → 广播新配合表，并回执新配合 id；客户端**自动打开树形界面并展开定位到这条新配合**。
6. 类型/数值之后可以在树形界面里改（换类型 = 删掉重建，会重新吸附）。

**配合模式下左键/中键一律吞掉** —— 必须完全接管手杖交互，否则会一边选配合一边触发拖拽。

## 7. 冲突检测

判定逻辑本身是纯函数 `MateFrames.Budget`（可离线验证），`MateRegistry.overConstrained` 只负责
把「同一对结构上已有的配合」喂给它，再加上本次要建的那一条。

规则要点（旧版本文只按 `lockedAxes` 计数，是错的，已修正）：

1. **限制轴也要计入**。DISTANCE / TANGENT 这类配合没有把轴锁在 0，而是用
   `setLimit(axis, v, v)` 把它**钉在非零值 v** 上 —— 从自由度角度看和锁死是同一回事，只是定在 v。
   旧逻辑只看 `lockedAxes`，于是「距离 5」和「距离 8」叠在同一根轴上会被判为不冲突。
2. **冲突 = 同一根轴被钉在两个不同的值上**（或者一个要求归零、一个要求非零），而不只是「超过 3 个」。
   同一根轴被钉在同一个值上是重复而非冲突。
3. **轴先按方向去重**：每个方向最多 3 个自由度，所以「某方向轴数 > 3」永远不会发生，
   `Budget.exhausted()` 曾经因此是死代码，已删。
4. **顶点参考不产生角向自由度**。顶点没有方向，把它和另一个点做重合只消掉 3 个线性自由度；
   旧逻辑按「参考有没有方向」漏算过，会让「顶点—顶点重合」被错误地记 2 个角向轴。

另外拒绝：两端同一个体、完全重复的配合、方向类配合有一端没有方向、结构属于其他玩家、
需要吸附的距离超过 `MAX_SNAP_DISTANCE`（64 格）。

## 8. 落盘

`MateData`（每维度一份 `SavedData`）只存配合的**描述**；关节句柄是运行期对象，不能序列化，
进入世界后由 `MateRegistry.physicsTick` 按当前位姿重建。结构被移除时其配合一并丢弃。

## 9. 已知限制

1. **不重新吸附的重建**：关节失效后按当前位姿重建，所以如果结构在被推歪的状态下重建，
   歪掉的状态会被当成新的基准（约束仍然自洽，只是不再是原始装配姿态）。
2. **过约束检测是近似的**：按轴计数而不是真实自由度求解，可能出现漏判/误判。
3. **距离配合不约束姿态**：与 SolidWorks 一致，标准的距离配合只定距离；两面是否平行要靠另加平行配合。
4. **相切是「平行 + 间距」的近似**：没有真正的圆柱/球解析几何，用结构主轴或面的法线代替。
5. **方块级参考会随方块失效**：参考的方块被挖掉后该配合的几何就没有意义了。
6. **两个已配合的结构之间关闭接触**（`setContactsEnabled(false)`）：否则共面的两个面会被接触力顶开、
   与关节对抗。副作用是配合后两者不再互相碰撞，这与现有「无碰撞」功能的语义一致。
7. 高级配合（轮廓中心 / 对称 / 宽度 / 路径 / 线性耦合 / 限制）**尚未实现**，留待标准配合验证通过后补。
