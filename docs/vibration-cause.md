# 振动的根因与缓解（2026-10-03）

> **一句话结论**：静止时持续微振（含向不同方向的微小倾斜、缓慢自旋）**主要由【物理步长】
> 与【接触弹簧频率】的采样关系决定** ✓。用户的对照实验给出了决定性证据：

```
physics steps = 60    ⇒ 明显抖动 ✗
physics steps = 200   ⇒ 基本不抖 ✓✓
```

**⇒ 所以有效的旋钮是【Sable 的 `physics steps` 配置】** ✓ —— **不是代码里的常数** ✗

---

## 1. 机制（采样定理 ✓）

Sable 的接触**不是硬约束** ✗ —— Rapier 把它建模成**弹簧-阻尼** ✓：

```rust
// integration_parameters.rs
pub contact_softness: SpringCoefficients<Real>,   // natural_frequency + damping_ratio
```

```
步长 dt = 1 / (physics steps)
Nyquist 极限 = 1 / (2·dt)

steps = 20  ⇒ dt = 0.05 s  ⇒ 极限 10 Hz   ；而 Sable 用 30 Hz ✗ ⇒ 3 倍于极限 ⇒ 【振铃】
steps = 60  ⇒ dt ≈ 0.0167s ⇒ 极限 30 Hz   ；30 Hz 恰好【骑在极限上】✗ ⇒ 仍振 ✓（与实测一致 ✓）
steps = 200 ⇒ dt = 0.005 s ⇒ 极限 100 Hz  ；30 Hz 【远低于极限】✓ ⇒ 不振 ✓✓（与实测一致 ✓）
```

**⇒ 三条实测与理论逐点吻合** ✓✓ —— **这是目前对振动最可靠的解释** ✓

**⚠ 而 `damping_ratio = 5.0`（强过阻尼）压不住它** ✗ ——
**因为【采样不足是离散化问题】✗ 不是振幅问题** ✓（过阻尼只能减小振幅 ✓ 消除不了步进过冲 ✗）

## 2.1 更正：1、2 两条"无反应"是【假的无反应】✗✗

后来查实：那两处原生常数**在源码里从来没被改过** ✗ ——
当时是用 PowerShell 的 `-replace` 往 `lib.rs` 里塞的 ✓，
而 **`-replace` 的模式没匹配上时【静默什么都不做】** ✗：
`cargo build` 照样成功 ✓（常量没人引用 ⇒ 不会有编译错误 ✗），
于是"编了一份新 DLL"✗ —— **而 DLL 哈希确实变了** ✓（因为同期还有别的改动 ✓）
⇒ **我看到哈希变了，就判定"改动生效了"** ✗✓ ← **这就是漏掉的那一环** ✗。

**⇒ 因此**：
- 这两条**不能算"原生常数无效"的证据** ✗ ⇒ 它们**还没被真正试过** ✓；
- 上一版写在这里的"**强烈提示 Java 配置覆盖了这些字段**"✗
  —— **这个怀疑目前没有任何证据支持** ✗✓（很可能是错的 ✓）。

## 6. 可靠性的教训（比结论本身更重要 ✓）
