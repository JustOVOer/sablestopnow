# 事故复盘：凸包突然没有碰撞（2026-10-03）

> 这份文档的目的是**不再重犯** ✓。事故本身只损失了一个来回 ✓，
> 但它暴露了**七类可避免的错误** ✗，而每一类都有对应的硬规则 ✓。

## 1. 事故链（三步，每步本可避免 ✓）

### ① 触发：JNI 返回长度改了一端，没改另一端 ✗

我为测"接触身份命中率"（`idHits / idMints`），把 `bodyState` 的返回值从 11 个扩到 14：

```rust
// convex.rs —— 我改的
let mut out = [0.0_f64; 14];     // ✗ 改成了 14
...
out = [ …11 个原值…, 0.0, 0.0, 0.0 ];   // ✗ 也补了 3 个

// 但下面这行【没改】✗✗
match env.new_double_array(11) {        // ✗ 仍然是 11
```

**⇒ JNI 往 11 槽的数组里写 14 个值** ✗ ⇒ 运行时抛：

```
java.lang.ArrayIndexOutOfBoundsException: Array region 0..14 out of bounds for length 11
    at VoxelCollisionService.attachConvex(VoxelCollisionService.java:669)
```

**⇒ `attachConvex` 抛异常 ⇒ 凸包根本没挂上 ⇒ 【没有碰撞】** ✓
**⇒ 而 Sable 自己的结构不走这条代码 ⇒ 它们照常有碰撞** ✓✓

> **用户的那句观察是定位它的关键** ✓：
> "没碰撞的是我们的凸包模型，sable 的物理结构仍有碰撞。是不是我们重载的逻辑有问题"
> ⇒ 这句话把范围从"物理引擎"直接缩到"我们的挂载路径" ✓✓ —— 比我自己猜快得多 ✓

### ② 为什么没在交付前发现 ✗

| 环节 | 为什么没拦住 |
|---|---|
| **原生编译** | **通过了** ✗ —— 长度不匹配是**运行时**错误 ✓ 编译期看不见 ✓ |
| **模组构建** | 报 `BUILD SUCCESSFUL` ✗ —— 但它**同步的是旧 DLL** ✗ |
| **我的自检** | 我漏了"改完先读日志"这一步 ✗✓ ← **最刺痛的一条** |

### ③ 为什么连续 5 次"回退"都无效 ✗✗✗

三重原因叠加 ✓：

```
a) depends/ 不在 git 里 ✗
   ⇒ git reset --hard 只恢复了 src/ ✗ 【碰不到原生源码】✗

b) cargo 使用 target/ 缓存 ✗
   ⇒ 只删 DLL 没用 ⇒ 它报 "Finished in 0.81s" 而【什么也没编】✗

c) 模组的 BUILD SUCCESSFUL 掩盖了原生的失败 ✗
   ⇒ 我只看最后一段 ✓ 而前一段（原生）其实失败了 ✗
```

**⇒ 三者叠加 ⇒ 我每次"回退成功"实际都在跑同一份坏 DLL** ✗✓

## 3. 七条硬规则（每次改动都照做 ✓）

| 规则 | 做法 | 防住 |
|---|---|---|
| **R1 · 接口改两端** ✓ | 改任何 JNI / 序列化长度时，**在同一个 edit 里改两处** ✓ | 根因 1 |
| **R2 · 验证产物** ✓✓ | 回退或改原生后，**必须对比 DLL 哈希** ✓ 且**耗时应为分钟级** ✓（0.8 秒 = 假重编 ✗）| 根因 4 |
| **R3 · 看前段** ✓ | **先看原生的 `Compiling` / `Finished`** ✓ 再看模组的 `BUILD SUCCESSFUL` ✓ | 根因 5 |
| **R4 · 先读日志** ✓✓ | **改完立刻读日志确认无异常** ✓ 异常会点名文件与行号 ✓ | 根因 6（**最省时间** ✓）|
| **R5 · 验证环境假设** ✓ | `git check-ignore depends/` ✓ 确认哪些目录**不受版本控制** ✓ | 根因 3 |
| **R6 · 单一变量** ✓ | 一次只改一处 ✓（本轮我同时改了 `bodyState` 与身份逻辑 ✗）| 缩小定位范围 ✓ |
| **R7 · 回读 + 正向证据** ✓✓ | **脚本改完源码必须【回读】确认真的改到了** ✓；而且**新符号要有编译期或运行期的【正向证据】** ✓ —— 没人引用就不会有编译错误 ✗，"DLL 哈希变了"也**不等于这处改动进了** ✗ | §5 |

### 而一条流程改动就能防住全部 ✓✓

> **改完 → 编译 → 【读日志确认无异常】→ 才交给用户**
>
> 我在整个会话里都遵守"改完自己读日志"✓，
> 但这一轮【在让用户测之前】漏了第三步 ✗✓ —— 如果我读了，就会当场看到那个异常 ✓，
> **用户根本不用碰到这个事故** ✗

## 4. 环境事实（本来该早确认的 ✓）

| 事实 | 影响 |
|---|---|
| **`depends/` 不在 git 里** ✗ | `git reset` **不会**恢复原生源码 ✓ ⇒ **原生改动必须手工备份** ✓ |
| **cargo 用 `target/` 缓存** ✗ | 只删 DLL **不能**强制重编 ✓ ⇒ **要删整个 `target/release`** ✓ |
| **原生产物不在 jar 的构建依赖里** ✗ | 原生失败时模组仍会"成功"✓ ⇒ 必须看原生那一段 ✓ |
| **`gradlew clean` 会因目录被占用而半途失败** ✗ | 会留下缺文件的 `build/` ✓ ⇒ 之后 `prepareClientRun` 报错 ✓ ⇒ 需手工删 `build/` ✓ |
| **Sable 的 Rust `log::warn!` 不进游戏日志** ✗ | 诊断值要走 JNI 返回（如 `bodyState`）✓ —— 这也是本次改动的动机 ✓ |

## 5. 第二起（同一类错误 ✓）：不存在的构建号，与两条"假的无反应"实验

### ① 现象

实机日志里每次挂凸包都出现一条 ERROR ✗（2026-10-03 15:27 ✓）：

```
[native] 无法读取构建号（DLL 里没有 nativeBuildId ✗）
java.lang.UnsatisfiedLinkError: 'long com.ovo.sablestopnow.physics.SablePhysicsExt.nativeBuildId()'
    at …SablePhysicsExt.<clinit>(SablePhysicsExt.java:53)
```

### ② 成因

**"原生构建号"这个机制，Rust 那一半从来就不存在** ✗：

| 侧 | 当时的真实情况 |
|---|---|
| Java ✓ | `nativeBuildId()` 声明了 ✓、静态块里调用了 ✓、日志也写了 ✓ |
| **Rust** ✗✗ | **`NATIVE_BUILD_ID` 常量没有 ✗**、**`Java_…_nativeBuildId` 导出没有 ✗** |

原因是**用 PowerShell 的 `-replace` 往源码里塞的** ✗，
而 **`-replace` 模式不匹配时【静默返回原串】** ✗ —— 不报错 ✗ 不提示 ✗。
`cargo build` 当然照样成功 ✓（**没人引用那个常量 ⇒ 没有编译错误** ✗），
于是每次挂凸包都打一条 ERROR ✓，而**"启动标志"这条需求从头到尾没生效过** ✗✓。

### ③ 连带后果（更贵 ✗）

同一手法还改过两处原生常数 —— **`friction_model: Coulomb`** 与
**`natural_frequency` 30 → 8** ✗。它们**同样没进源码** ✗，
所以那两次"实测无反应"**是假的无反应** ✗✓，
而当时得出的结论是"**很可能被 Java 侧配置覆盖**"✗ —— **这个推断是错的** ✗
（已更正：`docs/vibration-cause.md` §2.1 ✓）。

**⇒ 代价**：两条本可有效的实验被误判为"无效" ✗，并在此基础上写了一段错误的归因 ✗。

### ④ 这一次靠什么发现 ✓

**靠 R4（改完先读日志）** ✓ —— 而且关键是：**日志里那条 ERROR 一直都在** ✗✓
（更早几轮的实机日志里也有 ✓），只是我当时**没读**就把它当成正常 ✓。
**⇒ 规则没有失效 ✗，是我没有执行** ✓。

### ⑤ 加固措施（已做 ✓）

| 措施 | 说明 |
|---|---|
| **Rust 侧真的加上** ✓ | `convex.rs`：`pub const NATIVE_BUILD_ID` + `#[unsafe(no_mangle)] Java_…_nativeBuildId` ✓ |
| **改成【构造期】打标志** ✓ | 静态块只在"首次用到这个类"时跑 ✗ ⇒ 标志会推迟到实机第一次挂凸包 ✗。现在由 `SablestopNow` 构造器调用 `SablePhysicsExt.initNative()` ✓ ⇒ **每次启动必然一行** ✓ |
| **DLL 里查得到** ✓ | 构建后用 ASCII 扫描 DLL，确认导出名确实在里面 ✓（正向证据 ✓）|
| **报错要打全** ✓ | 原来只打一句"不匹配" ✗，看不到 `UnsatisfiedLinkError` ✗ ⇒ 现在把异常整个打出来 ✓ |
