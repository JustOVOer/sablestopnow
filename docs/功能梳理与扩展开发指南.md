# SableStopNow —— 功能梳理与扩展开发指南

> 面向开发者的说明文档，梳理本 NeoForge 模组现有的功能与实现路径，
> 并给出“添加新功能”的接线清单与建议，方便后续扩展。
>
> 目标环境：Minecraft 1.21.1 + NeoForge 21.1.248 + **Sable**（物理引擎）+ **Simulated / Aeronautics**（航空学，做物理体锁定）+ Create（可选）。
> 本模组本身不注册方块/物品/实体，**全部通过 Mixin 改写 Sable/Simulated 逻辑** 以及 **NeoForge 事件 / 命令 / 配置** 实现。

---

## 1. 定位与核心思路

SableStopNow 的目标是：**对 Sable 物理引擎施加在“物理体(sub-level)”上的力做监控与限制**，并附带几个工程辅助功能。

实现哲学：不 fork Sable，而是用 **Mixins 在关键方法上打点**，加上 **编译期依赖（compileOnly）** Sable/Simulated 的 API 与类，运行时依赖对应的 mod jar（本地 `libs/` 提供 veil、ForgeConfigAPIPort、create）。

**最关键的改动点（一个 Mixin 就解释了整套机制）：**

| Sable 内部调用链 | 触发点 | 作用 |
|---|---|---|
| `ServerSubLevel.getOrCreateQueuedForceGroup()` | 每次给某物理体“排队”一个力组时 | 把 `QueuedForceGroup → 力组ResourceLocation` 记进缓存，供过滤用 |
| `QueuedForceGroup.applyAndRecordPointForce()` | 真正把点力施加到物理体 | 按阈值过滤/丢弃、自动暂停、记录 |
| `SubLevelPhysicsSystem.tickPipelinePhysics()` | 每物理刻结束 | 把“这一刻”的记录归档为展示列表 |
| `SubLevelHeatMapManager.step()`→`split()` | 热力图把物理体切分 | 切分前的玩家确认流程 |
| `SubLevelAssemblyHelper.assembleBlocks()` | 切分/组装新物理体 | 新建物理体后自动“锁定” |
| `BlockPlaceContext.canPlace()` | MC 放方块碰撞检测 | 允许在别的物理体内放方块 |

简言之：**“力过滤” = 缓存力组ID + 在施加力时 HEAD 拦截丢弃**；其余功能各自是一个独立的 Mixin 小钩子。

## 2. 代码结构总览

所有代码都在 `com.ovo.sablestopnow`（服务端/双端逻辑）与 `com.ovo.sablestopnow.client`（客户端渲染）包下。

```
src/main/java/com/ovo/sablestopnow/
├─ SablestopNow.java               # @Mod 入口：注册配置、命令、静态“力记录”存储
├─ SablestopNowConfig.java         # ModConfigSpec 全部配置项（COMMON 型）
├─ ForceCommand.java               # /sablesn ... 命令树与展示
├─ ForceRecord.java                # 单条“力记录”的只读数据类
├─ ForceGroupCache.java            # WeakHashMap: QueuedForceGroup -> ResourceLocation(力组ID)
├─ SplitConfirmationManager.java   # 切分确认的挂起请求表 + 执行/取消
├─ ModRenderTypes.java             # 自定义 RenderType（描边线条）     ★声明包 .client
├─ SubLevelOutlineRenderer.java    # 客户端物理体描边渲染            ★声明包 .client
└─ mixin/
   ├─ QueuedForceGroupMixin.java        # 核心：力过滤 / 记录 / 自动暂停
   ├─ ServerSubLevelMixin.java          # 填充 ForceGroupCache
   ├─ SubLevelPhysicsSystemMixin.java   # 物理刻边界 finalizeTick()
   ├─ SubLevelHeatMapManagerMixin.java  # 切分确认拦截 + 清热力图数据
   ├─ SubLevelAssemblyHelperMixin.java  # 新建物理体自动锁定
   └─ BlockPlaceContextOverrideMixin.java # 放方块碰撞检测开关

src/main/resources/
├─ sablestopnow.mixins.json        # 6 个 Mixin 的注册清单（都在公共 mixins 列表）
└─ assets/sablestopnow/lang/{en_us,zh_cn}.json   # 多语言文案
src/main/templates/META-INF/neoforge.mods.toml   # 通过 ${} 展开的模组元数据
```

> ⚠️ **目录/包不一致（已确认）**：`ModRenderTypes.java` 与 `SubLevelOutlineRenderer.java`
> 声明 `package com.ovo.sablestopnow.client`，但**物理路径**却放在 `com/ovo/sablestopnow/` 根目录
> （没有 `client/` 子目录）。Java 允许“声明包 ≠ 目录”，所以能编译能跑，但非常容易误导。
> **新增客户端类时建议**：要么把这两个文件挪进真正的 `client` 子目录，要么新增类就放根包并写 `package com.ovo.sablestopnow;`。
> 注意 `SubLevelOutlineRenderer` 目前是通过 `@EventBusSubscriber` + `import com.ovo.sablestopnow.client.ModRenderTypes` 正常工作的，编译期没有真正按目录解析，所以暂时无碍。

### 注册资源
- Mixin：`neoforge.mods.toml` 里 `[[mixins]] config = "sablestopnow.mixins.json"`。
- 新增 Mixin 时**必须**同步在 `sablestopnow.mixins.json` 的 `mixins`（或 `client`/`server`）数组里加类名，否则不生效。

## 3. 运行时装配（入口）

### 3.1 `SablestopNow`（@Mod 主类）
- `@Mod("sablestopnow")`，构造器里：
  1. `container.registerConfig(ModConfig.Type.COMMON, SablestopNowConfig.SPEC, MOD_ID + "-common.toml")` → 配置文件生成于 `config/sablestopnow-common.toml`。
  2. `NeoForge.EVENT_BUS.addListener(this::registerCommands)` → 在 `RegisterCommandsEvent` 里挂 `ForceCommand.register(dispatcher)`。
- 同时它是一个**静态数据中心**：
  - `currentRecords`：当前物理刻累积的新力（`recordForce` 往里加，自动去重）。
  - `displayRecords`：上一物理刻归档的展示快照（供命令读取）。
  - `hasNewForces`：标记“这一物理刻有没有新力”，供命令提示“显示的是旧数据”。
  - 方法全部 `synchronized`（物理线程/主线程并发调用，粗粒度锁保证线程安全）。
- `finalizeTick()` 由 `SubLevelPhysicsSystemMixin` 在每个物理刻 RETURN 时调用：把 `currentRecords` 整体拷成 `displayRecords` 后清空 `currentRecords`。

### 3.2 配置 `SablestopNowConfig`
所有项都包在 `push("force_limiter")` 段内，配置 key 形如 `sablestopnow.force_limiter.<name>`。

> 当前**配置键名**（TOML 里的名字）与 README 有出入，README 没跟上后期加的描边/坐标轴配置。下表为准。

| 字段（TOML key） | 类型 | 默认 | 作用 |
|---|---|---|---|
| `filter_excessive_force` | bool | false | 是否开启超限力过滤 |
| `threshold` | double | 1000.0 | 力阈值（Sable 单位），超过即丢弃 |
| `excluded_groups` | string[] | [] | 豁免的力组ID（如 `sable:gravity` 放行） |
| `max_records` | int | 1000 | （预留）内存保留记录上限，当前代码其实未严格按它裁剪 |
| `auto_pause_on_filter` | bool | false | 一旦过滤掉某力→暂停该世界物理体并广播，随后**自动复位为 false** 并 save |
| `lock_new_sub_levels` | bool | false | 新建物理体时用 Simulated 的 PhysicsStaff 锁定 |
| `disable_placement_collision_check` | bool | false | 放方块时跳过与其他物理体的碰撞检查 |
| `require_confirmation_before_split` | bool | false | 物理体切分前需玩家 /sablesn confirm |
| `render_sub_level_outlines` | bool | false | 客户端给物理体表面方块描彩色边框 |
| `outline_always_visible` | bool | true | 描边忽略深度测试（透过墙可见） |
| `outline_only_contour` | bool | false | 只描暴露在空气中的“轮廓边” |
| `outline_only_focused` | bool | false | 只描玩家当前注视(准星所指)的物理体 |
| `render_axis` | bool | false | 在每个物理体中心画三色坐标轴 |
| `axis_angle_degrees` | double | 5.0 | 坐标轴臂相对相机的张角，据此换算屏幕恒定大小 |

> 备注：`filter_excessive_force`、`auto_pause_on_filter` 是“单次触发”型；`auto_pause_on_filter` 触发后会把自身写回 false 并落盘，这是有意的“防反复触发”。

### 3.3 多语言
- 键集中在 `en_us.json` / `zh_cn.json`。命令提示、切分广播、自动暂停广播都走 `Component.translatable(...)`。
- **有一批遗留/无用的键**：`itemGroup.sablestopnow`、`example_block/example_item`、`configuration.title`、`logDirtBlock`、`magicNumber*` 等是脚手架残留，可清理。
- 新增可本地化文案 = 在 `SablestopNowConfig` 加 `.translation(...)` + 在两张语言文件各加一条 + 代码用 `Component.translatable(key, ...)`。

## 4. 功能与实现逐项拆解

### 4.1 【核心】力过滤、记录、自动暂停
**目标效果**：超过阈值的力被丢弃（不生效），并记录/提示。

调用链（Mixin 之间如何配合）：
1. `ServerSubLevelMixin` @Inject `getOrCreateQueuedForceGroup` 的 **RETURN**，把 `queued → 力组ID` 写入 `ForceGroupCache`（WeakHashMap，键为 QueuedForceGroup）。
2. `QueuedForceGroupMixin` @Inject `applyAndRecordPointForce`（签名 `(Vector3dc point, Vector3dc force, CallbackInfo)`，**remap=false**，@At HEAD，**cancellable**）：
   - 从缓存查力组ID；查不到且开启了过滤→打 warn 并放行（不拦）。
   - 若 `filter_excessive_force` 关闭 → 仅 `recordForce(force,false,…)` 后 return。
   - 否则 `magnitude = force.length()`；若 `magnitude > threshold` **且** 力组不在 `excluded_groups` → `ci.cancel()` **真正把该力吞掉**。
   - 吞掉后若 `auto_pause_on_filter`：取 `subLevel.getLevel()` → `SubLevelPhysicsSystem.get(level).setPaused(true)`，对全服玩家广播 `/sablesn forces` 建议；随后把配置复位 false 并 `saveConfig()`。
   - 无论过滤与否都调用私有 `recordForce(...)`（注意：**即使被 cancel 也记录为 filtered=true**）。
3. `SubLevelPhysicsSystemMixin` @Inject `tickPipelinePhysics` 的 **RETURN** → `SablestopNow.finalizeTick()`，把本物理刻记录归档。

`recordForce` 里把 `displayName` 由 `ForceGroups.REGISTRY.get(id).name()` 解析出来（拿不到就用 ID 字符串）。记录的 position 用 `subLevel.logicalPose().position()`（物理体原点）。

> 陷阱提示：
> - **过滤真正生效靠的是 HEAD + cancellable 拦截**，丢力发生在 Sable 把力写进物理引擎之前，安全。
> - `recordForce` 的“存在相同即跳过”去重，比较用 `double ==` 精确相等（`getMagnitude()`），连续刻可能同一数值不重复记录，可接受。
> - `ForceGroupCache` 的 key 用 **WeakHashMap**，一旦 Sable 侧不再持有 QueuedForceGroup，缓存条目会被回收；此时下一次 `getOrCreateQueuedForceGroup` 又会重新填充，所以基本能自愈。

### 4.2 切分（split）确认
**目标效果**：物理体被热力图判定应切分时，先征得玩家同意，避免意外把结构切碎丢部件。

- 触发点：`SubLevelHeatMapManagerMixin` 把 `step()` 内**两处** `this.split()` 调用（ordinal 0 与 1）用 @Redirect 替换成 `sablestopnow$handleSplit()`。
- `handleSplit()` 逻辑：
  - 配置未开 → 直接调回原生 `this.split()`（@Shadow）。
  - 开了且该物理体已有挂起请求 → return（不重复发）。
  - 把 `subLevelSplits` 键集（long 打包的 BlockPos）收集成 blocks，`BoundingBox3i.from(blocks).expand(1,1,1)` 得到边界 → `SplitConfirmationManager.addPendingRequest(uuid, level, blocks, bounds)`，并全服广播“请输入 /sablesn confirm 或 deny”。
- `ForceCommand` 的 `/sablesn confirm|deny` 调 `SplitConfirmationManager.confirmSplitForLevel/denySplitForLevel`（按当前命令所在 world 匹配挂起请求）。
- `confirmSplit(uuid)`：从挂起表取出请求 → `SubLevelAssemblyHelper.assembleBlocks(level, anchor, blocks, bounds)` 真正执行切分 → 若新物理体质量非法则销毁并移除 → 反射调用热力图上 Mixin 注入的 `sablestopnow$clearSplitData()`（见下）。
- `denySplitForLevel`：直接移除挂起请求并清热力图数据。

> 关于反射：`clearHeatMapData` 通过 `getDeclaredMethod("sablestopnow$clearSplitData")` 反射调用 `SubLevelHeatMapManagerMixin` 加的 `@Unique` 方法。Mixin 的 `@Unique` 私有方法目标名里确实会带 `sablestopnow$` 前缀，所以能命中，但**脆弱**（依赖命名前缀约定，Sable 升级/混淆变化可能崩），是已知隐患。
> `sablestopnow$clearSplitData()` 把 `subLevelSplits`、`splitIndexMap`、`floodfill/removed/newStarts` 清空、state 置 `CLEARING`、`splitComplete=true`，用来终止热力图继续切分该物理体。

### 4.3 新建物理体自动锁定
**目标效果**：`lock_new_sub_levels` 开启时，凡是 `SubLevelAssemblyHelper.assembleBlocks` 新建出来的物理体自动用“固定约束”锁住。

- `SubLevelAssemblyHelperMixin` @Inject `assembleBlocks`（static）的 RETURN → 配置开且返回值非空 → `PhysicsStaffServerHandler.get(level).toggleLock(subLevelId)`（**来自 Simulated / Aeronautics**，实现与“航空学模组”的物理手杖同款锁定）。
- 这是本模组与 Simulated 的唯一硬依赖点。README 说明：装了航空学才有意义，否则锁不回来（要靠它才能解）。

### 4.4 放方块碰撞检查开关
- `BlockPlaceContextOverrideMixin` @Inject `BlockPlaceContext.canPlace`（HEAD，cancellable）→ 配置开则 `cir.setReturnValue(true)`，允许把方块放进已有物理体占用的空间。

### 4.5 客户端物理体描边 / 坐标轴
- 纯 NeoForge 客户端事件，无 Mixin。
- `SubLevelOutlineRenderer`：`@EventBusSubscriber(Dist.CLIENT)`，订阅 `RenderLevelStageEvent`，仅在 `AFTER_ENTITIES` 阶段画。
  - 遍历 `ClientSubLevelContainer.getAllSubLevels()`，过滤已移除、过滤超距离（`MAX_RENDER_DISTANCE=64`）、可选只画准星注视的那一个（`Sable.HELPER.getContaining` 反查所在物理体）。
  - 颜色由 `uuid.hashCode()` 的 RGB 字节稳定生成；`alwaysVisible` 时会略放大方块（0.98+扰动）避免 z-fighting。
  - 逐 loaded chunk section 扫非空气方块，只对“至少一个面贴空气”的 `isSurface` 方块：
    - 全边框模式 `drawBlockOutlineFull`：`LevelRenderer.renderLineBox` 画整块 12 条棱线（返回固定 12）。
    - 轮廓模式 `drawBlockOutlineContour`：只画“暴露且非内折”的边（做了共面去重 skip 逻辑），逐边 `addLine`。
  - 可选 `drawAxis`：在物理体原点画 XYZ 三色轴，臂长按 `dist*tan(angleDeg)` 换算成近似屏幕恒定大小。
  - 最后统一 `bufferSource.endBatch(renderType)`。
- `ModRenderTypes`：定义两条线框 RenderType（顶点格式 POSITION_COLOR_NORMAL，模式 LINES，线宽 2.0，透明，NO_CULL）：
  - `LINES`：LEQUAL 深度测试（正常遮挡）。
  - `LINES_NO_DEPTH`：NO_DEPTH_TEST（穿墙可见）。

> 性能注意：它逐 tick 遍历每个物理体每个 section 的每个方块做空气面判断并提交线框，物理体/方块多时开销不小，且只按离相机距离（不含视锥剔除）粗筛。

### 4.6 力记录查看命令 `/sablesn`
命令树（`/sablesn`）：
```
forces [page]           # 查看所有力（分页 10 条/页）
forces filtered [page]  # 只看被过滤的
confirm                 # 确认切分
deny                    # 取消切分
```
展示特性：
- 无新力时提示“显示上一物理刻数据”（`old_data_hint`）。
- 记录按幅值降序。
- 目标物理体 ID 做成“点击填充 `/tp @p x y z`”的组件；页眉/翻页 `[上一页]/[下一页]` 可点击跳转（RUN_COMMAND）。
- 过滤状态红字 `[已过滤]` / 绿字 `[正常]`。

## 5. 数据流时序（一图流）

```
 物理线程/主线程
 [物理刻 N]
   ServerSubLevel.getOrCreateQueuedForceGroup()  ──mixin─▶ ForceGroupCache 填充 (queued→id)
   QueuedForceGroup.applyAndRecordPointForce()    ──mixin─▶ 过滤(cancel丢力)/自动暂停/recordForce()
        │ currentRecords
   SubLevelPhysicsSystem.tickPipelinePhysics()    ──mixin─▶ finalizeTick(): current→display, hasNewForces
   [玩家] /sablesn forces                          ──▶ getForceRecords() 读 displayRecords 展示
```

## 6. 如何扩展 —— 通用“加功能”清单

新功能大多落在这几类里，先判断属于哪一类再找对应接线点。

### A. 加一个**配置开关/数值**
1. `SablestopNowConfig.Config` 构造器里 `force_limiter` push 段内加一个字段（`BooleanValue`/`DoubleValue`/`IntValue`/`ConfigValue<List>`）。
2. 需要工具提示→加 `.translation("config.sablestopnow.<...>")` 并在 `zh_cn.json`/`en_us.json` 加对应文案。
3. 在对应 Mixin / 事件处理器里读取 `SablestopNowConfig.INSTANCE.xxx.get()`。
4. `saveConfig()` 已存在（`SablestopNow.saveConfig()`），触发后可 `SablestopNowConfig.INSTANCE.xxx.set(...)` + save。
5. 若改了默认值想要生效需要新建世界/手动改 toml（NeoForge 配置不改默认，已生成文件不会自动回写）。

### B. 对**力的新处理规则**（新的过滤维度/分流/统计）
入口就是 `QueuedForceGroupMixin.sablestopnow$recordForce(...)` 或整个 HEAD 注入逻辑：
- 想要拦截某种力：在 HEAD 里加判断，需要丢弃就 `ci.cancel()`。
- 想记录更多字段（力方向、作用点、所属物理体名称…）：扩展 `ForceRecord` + 构造处传参，再到 `ForceCommand`/语言文件里展示。
- 想分统计维度：可在 `SablestopNow` 静态类里加累加器，用 `finalizeTick()` 做刻边界汇总。

### C. 挂一个新的 Sable/Simulated/原版 **Mixin 钩子**
1. 确认目标方法名与签名（先读 `sable-main` / `Simulated-Project-main` 源码确认，编译期依赖里 `remap=false` 表示非 Minecraft 方法）。
2. 新建 `com.ovo.sablestopnow.mixin.XXX`，`@Mixin(目标类)` + `@Inject/@Redirect/@ModifyVariable`（注意 @At 选择 & `cancellable`）。
3. **把新类名加进 `src/main/resources/sablestopnow.mixins.json`**（`mixins`/`client`/`server` 数组）。
4. 若给目标注入 `@Unique` 方法会被别处反射调用，注意命名前缀与脆弱性（见 4.2）。

### D. 新增一条**聊天/提示/广播**组件
用 `Component.translatable("sablestopnow.xxx.yyy", args...)` 组装，可套 `ClickEvent`/`HoverEvent`；在两个语言文件补键；若要“命令建议”沿用 `ClickEvent.Action.SUGGEST_COMMAND`、要“直接执行翻页/子命令”用 `RUN_COMMAND`。

### E. 新增一条 `/sablesn` **子命令**
在 `ForceCommand.register(...)` 的 `.then(...)` 链里加字面量 + executes；复用 `SablestopNow`/`SplitConfirmationManager` 之类状态；文案走语言文件。

### F. 新增**客户端渲染**叠加
在 `SubLevelOutlineRenderer`（改/加绘制）或新建 client 事件订阅（`@EventBusSubscriber(Dist.CLIENT)` + `RenderLevelStageEvent`）；自定义材质参考 `ModRenderTypes`。**记得注意包/目录不一致问题（见 §2）。**

## 7. 加功能前请先核对依赖源码

扩展对象是别人的 mod，因此**任何新 Mixin 之前，先在依赖源码里确认方法签名/生命周期**：

- `sable-main/`（多模块：`common` 放 API，`neoforge`/`fabric` 平台侧，`sable_rapier` 物理后端）
  - 力相关：`dev.ryanhcode.sable.api.physics.force.{ForceGroup,ForceGroups,QueuedForceGroup}`
  - 物理体：`dev.ryanhcode.sable.sublevel.{ServerSubLevel,ClientSubLevel,SubLevel}`、`api.sublevel.*Container`
  - 组装：`dev.ryanhcode.sable.api.SubLevelAssemblyHelper`、`sublevel.storage.SubLevelRemovalReason`
  - 物理系统：`dev.ryanhcode.sable.sublevel.system.SubLevelPhysicsSystem`
  - 热力图：`dev.ryanhcode.sable.sublevel.plot.heat.SubLevelHeatMapManager`

## 8. 已知问题 / 隐患（扩展时优先处理）

1. **目录/包不一致**：两个 client 类声明 `package …client` 却在根目录（见 §2）。视觉误导大，建议修正目录。
2. **反射调 Mixin 私有方法**：`SplitConfirmationManager.clearHeatMapData()` 靠 `getDeclaredMethod("sablestopnow$clearSplitData")` 反射。依赖 Mixin 命名前缀，Sable 升级有风险。改进方向：换 @Accessor/@Invoker 或者把清理逻辑做成对外可见的方法。
3. **`max_records` 配置未真正强制生效**：读取保留上限却没有裁剪逻辑（内存展示列表越界只靠每物理刻覆盖快照）。可补“超出裁剪”。
4. **力记录线程安全用粗粒度 synchronized + 每次深拷贝 `new ArrayList`**：记录量大时开销偏大；且 `currentRecords` 用 `Vector3d`（可变），命令线程读取同一对象有潜在竞态。
5. **`auto_pause_on_filter` 触发即永久复位 false**：设计如此（避免反复触发），但如果希望“每刻都暂停直到玩家手动关”需要在广播后不再自动写回，改成手动开关。属于可迭代点。
6. **切分确认用“全服广播”**：不是发给触发者个人；多玩家/多物理体同时切分时共享一份 `PENDING_REQUESTS`（按世界/UUID 区分，单世界多物理体各一条，OK，但确认消息没绑定具体物理体名，容易对不上号）。
7. **描边渲染性能**：逐 tick 全量扫块，无视锥剔除，大体量结构卡顿风险；`outline_always_visible` 的缩放扰动用于防 z-fighting 属 hack。
8. **README 已过期**：它只写到 force 过滤那一代功能，没有 outline/axis 配置；编码在部分文件也乱（GBK/UTF-8 混杂），README 展示乱码，可重写。
9. **脚手架残留**：config 模板键、`example_block` 语言键等（§3.3）可清理。

## 9. 构建 / 运行速查

- 构建产物：`gradlew.bat build` → `build/libs/sablestopnow-*.jar`。
- 首次构建会 NeoForm 反编译，可能很久，非卡死。
- 运行时依赖放在本地：`libs/`（`create-1.21.1-6.0.10.jar`、`ForgeConfigAPIPort…jar`、`veil-neoforge…jar`）由 build.gradle `implementation files(...)` 引入。
- 编译 tip：新增 Mixin 后跑一次 client（`gradlew.bat runClient`）看是否注入成功（Mixin 目标找不到会在日志里直接报错）。

## 10. 扩展路线示例（供参考）

- 力过滤增强：按“力方向/目标物理体质量”分流，或加入“超出阈值改为衰减而非硬丢”。
- 更细的力记录面板：把 `ForceRecord` 扩展为含作用点、方向、时刻，命令加 `/sablesn details <id>`。
- 暂停原因溯源：暂停时记录是哪个物理体/哪个力组触发的。
- 让 `max_records`、切分确认请求体真正生效并做超时清理。
- 描边：给单个选中物理体单独高亮（非全量），并加视锥剔除。
