## 5. 诊断工具本身的已知缺陷 ✗（读数据时必须避坑 ✓）

### 缺陷 A：按 id 扫刚体不可靠 ✗✓
**做法**：为自动捕获"第二个结构"，曾扫 `id 0..23` ✓
**实测**：`id 3..23` **每一个都恰好 9551 个样本** ✗✓
**⇒ `bodyState` 对【不存在的 id】也返回非 null** ✗✗
**⇒ 结论**：**不能用 id 扫描来发现刚体** ✗ —— 已移除 ✓
**⇒ 正确做法**：显式 `HullTrace.trace(id, scene)` ✓；或按 `mass > 0 && colliders >= 1` 过滤 ✓

### 缺陷 B：`analyze-hull-trace.ps1` 的输出被控制台编码弄乱 ✗
**现象**：通过 `pwsh` 管道读取时中文变乱码 ✓
**⇒ 解法**：用 `tools\analyze-hull-trace.cmd`（带 `-ExecutionPolicy Bypass` ✓）✓
且 `.ps1` **必须存成 UTF-8 with BOM** ✓✓（否则 PowerShell 会把中文读坏 ✓ 会报 "missing terminator" ✗）

## 8. 凸包内凹（每面内收）—— 现在是**配置项** ✓

内凹量从写死的 Java 常量改成配置项 ✓（**单位 = 格** ✓ **默认 0.90** ✓ `0.0` = 完全不收 ✓）。

| 项 | 值 |
|---|---|
| 配置路径 | `config/sablestopnow-common.toml` → `[collision] hull_inset = 0.9` |
| 界面入口 | 设置界面（Ctrl+O）→ **物理组装器** → 分组「凸包碰撞 / Hull collision」|
| 生效时机 | **每次挂凸包时读一次** ✓ ⇒ 改名后**重建碰撞体**即生效 ✓（不用重启游戏 ✓）|
| 做成配置前的写死值 | `0.5` |

**收法必须是"按轴"** ✓（这是本项唯一的硬结论 ✓）：
```
按轴（现在 ✓）：k_轴 = 1 − inset / |d_轴|     ⇒ 每个面【精确】内移 inset 格 ✓
按半径（已否决 ✗）：k = 1 − inset / |d|        ⇒ 半径 6 / 高 ±1 的顶点：侧面内移 0.5 ✗、上下只内移 0.08 ✗
```
⇒ 半径收法的实机表现正是"**侧面收进去了、上下底面没收进去**"✗（你当场指出 ✓ 已改为按轴 ✓）

**为什么做成配置**：这个量对着的是【实机的视觉重合度】✓，只能一边看一边调 ✓ ——
以前写死在 Java 里，试一个数就要重编一遍原生库（约 5 分钟 ✗），现在改 toml 即可 ✓。

**退化保护**：每轴至少保留 **5%** 半宽 ✓（`k = max(0.05, 1 − inset / |d_轴|)` ✓）——
否则"内凹量 ≥ 该轴半宽"会把凸包压塌成一个平面 ✗，**正是之前"完全没有碰撞"那次的成因** ✗。
默认 0.90 对着 cap 的 1.0 半宽得到 k = 0.10 ✓ **碰不到这个下限** ✓。

**日志确认**：每次挂凸包都会打当前生效值 ✓
```
[sablestopnow] 凸包碰撞: solid=… 挂载刚体=… 顶点=112 内凹=0.900格 句柄=…
```
⇒ 直接读这一行就知道配置有没有被读到 ✓ 不用猜 ✗。
